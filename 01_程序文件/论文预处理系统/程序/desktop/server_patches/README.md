# 教育解析的服务器补丁

这些安装器只接受已核验的线上源码 SHA256，重复运行不改动已安装版本；遇到未知版本会停止，要求重新检查差异。它们不包含连接凭据，也不启动或停止服务。

## 执行日志

`education_execution_log/install.py` 修改 `api/db/services/pipeline_operation_log_service.py`：

- 仅教育主库的 Parse 日志使用会话锁，模型调用和索引不在锁内。
- 日志事务遇到 MySQL 1213 后完整回滚并有限重试，复用原日志 ID。
- 教育日志清理先确定过期记录的 ID，再按这些 ID 删除，仍保留最新 1000 条。
- 在事务开始后检查锁归属，拒绝在变更后的连接上继续写入。
- 其他知识库与非 Parse 日志保留原有处理。

`education_execution_log/mysql_retention_probe.py` 必须在具有 RAGFlow Python 环境的服务器中手动运行。它使用随机命名的隔离测试表，执行真实 create/retention 路径，结束时清理自己的表。`--real-dsl` 从教育库只读取得一条已完成日志作为真实大小的输入，不输出正文，也不修改原记录。

## 正文分块身份

`education_chunk_identity/install.py` 修改 `rag/svr/task_executor_refactor/dataflow_service.py`：教育正文和 AI 索引的默认分块 ID 加入来源位置和重复出现序号，避免相同文本在不同章节互相覆盖。原有显式 ID、附属材料及其他知识库沿用原规则。

## 部署与恢复

部署时先排空解析，再核对源码、执行安装器并重载执行器。安装器须放在持久挂载目录，并在已有启动安装步骤之后调用，才能在容器重建后继续生效。

每个源文件旁保存对应的原始备份。回退时先排空解析，核对当前源码与备份哈希，移除相应启动调用，再恢复备份并重载执行器。正文 ID 修复不会自动重建已完成的旧文档；已有来源校验失败的文档需保留原远端 ID 单独重解析。
