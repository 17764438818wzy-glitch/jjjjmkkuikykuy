# WorkBuddy 论文预提取：完整字段清单与交付规范

日期：2026-10-20。状态：讨论稿，供确定字段和交接格式使用。

本次只编写本说明，没有修改程序、处理论文、调用模型或启动入库。以下字段与流程是拟定的交付规范，不表示当前程序已经支持导入。

## 1. 明确建议

采用你提出的方式：**每篇论文由 WorkBuddy 完成一次主要内容理解，把结果保存到该论文文件夹；后续程序读取这些成果，保留完整正文、执行脱敏、生成切片并上传。**

沿用已经试跑的 **G1–G8＋segmentation**，保留已经提取正确的研究单元、图表解释、专业判断和使用限制。没有必要为换一套字段名重新读一遍论文，也没有必要重做工作台。

每篇只交付一个 `论文预提取.md` 可以成立。这个 MD 内含一个固定结构的 JSON 数据块，脚本直接解析它；前面可以有简短的中文说明，不必把全部内容再写一遍。已经有的 MD＋JSON 也能复用，无须删除或重新生成。

真正减少重复工作的条件是：**后续脚本消费已有成果，不再默认启动原来的三轮 LLM 处理。** 仅把原稿换成 MD，却仍让原链路完整重跑，不能达到这个目的。

按你目前能够免费使用 WorkBuddy 国际版 DeepSeek 的情况，这能减少你在现有链路上另付的模型费用；本规范不假设免费额度、速度或并发条件永久不变。一次主提取也不等于一次 API 请求：WorkBuddy 内部可能有工具往返、图片处理和重试。当前一篇 4 分 21 秒的截图不能证明批量吞吐或实际调用次数。

## 3. 每篇的文件组织

```text
某篇论文文件夹/
  原论文.docx 或 原论文.pdf          # 原件保留
  已有附件/                       # 只处理本次明确提供的附件
  论文预提取.md                    # WorkBuddy 生成的一份候选成果
  已有正文、索引、图片等提取成果      # 有就复用；没有则由提取工具生成
```

- `论文预提取.md` 主要保存画像、判断、来源引用和执行建议，不让模型重新抄写全部正文。
- 正文、表格、公式、图片仍由原稿或已有提取成果供程序取得。**画像不是正文替代品。** 如果没有可复用的完整提取正文，后续程序仍需做文件解析；图片型 PDF 的文字识别也不会因为有了画像而自动消失。
- MD 里的结构化数据块是脚本的唯一内容来源。简短中文说明用于阅读，不作为另一套不同结论。
- 候选 MD 可能包含脱敏原值、原始文件路径等内容，默认属于私有交接材料，不原样上传到 RAGFlow。
- 当前示例分开放置在“论文画像”目录。后续即使改成一篇一个文件夹，也要靠来源标识和原稿哈希核对，不只靠文件名或文件夹名猜匹配。

### 数据块约定

每份 MD 包含且只包含一个带下列标记的 JSON 代码块。JSON 不加注释、不加尾逗号；字段名固定。只输出可确定的内容，未取得的内容用 `null` 或空数组，并在 G8 说明重要缺口。

````markdown
<!-- paper-preextract:data:start -->
```json
{
  "schema_version": "workbuddy-preextract/1-draft",
  "source_binding": {},
  "G1_material_basic": {},
  "G2_chapters": {},
  "G3_research_process": [],
  "G4_borrowable": {},
  "G5_figures_tables": {"figures": [], "tables": []},
  "G6_major_classification": {},
  "G7_anonymization": [],
  "G8_gaps": [],
  "segmentation": {},
  "attachments": [],
  "one_line_profile": null
}
```
<!-- paper-preextract:data:end -->
````

以上只是外壳示例，空对象不表示内容已经完成。`schema_version` 是程序配置的格式标识，不由模型自行升级。本稿并未实现 JSON Schema 校验器或导入器。

## 4. 字段通用规则

下面的表格列出需要模型提供的语义内容。字段路径是建议的候选输出格式；沿用示例的外层分组，部分内部字段需要结构化。旧结果可以机械映射，不能把“格式改变”当成重新理解全文的理由。

“有则填”表示按原文实际情况填写；没有公式、实验或数值数据的论文，不为了凑字段虚构它们。所有材料都要有保留判断；正文被排除或暂无法判断时，不伪造后续完整画像。已提供附件独立判断。

| 通用字段／约定 | 谁提供 | 内容和规则 |
| --- | --- | --- |
| `source_refs[]` | LLM 引用，程序核验 | 关键结论、学习单元、图表和缺项引用实际输入中的块 ID、章节 ID、表格／单元格 ID 或图片 ID。章节名称可以辅助阅读，不能代替可执行位置 |
| `source_refs[].block_id` | 程序给 ID，LLM 选择 | 指向真实文本块；表格单元格和批注可使用提取工具提供的专用块 ID。模型不得临时编造“第 123 段” |
| `source_refs[].asset_id` | 程序给 ID，LLM 选择 | 指向实际图片或表格资产；只在相关时填写 |
| `source_refs[].start/end` | LLM 或定位工具，程序核验 | 需要精确文字跨度时填写，基于未修改文本，0 起始、结束位置不含在内，按 Unicode 码点计数；不得与字节数或 UTF-16 下标混用。普通概述可只引用完整块 |
| `source_refs[].source_kind` | LLM 判断 | `author_text` 原作者正文、`cited_work` 被引用研究、`reviewer_comment` 导师／评阅批注、`figure` 图片或 `table` 表格。不能把批注建议写成作者已经实施的研究 |
| `claim_status` | LLM 判断 | 需要区分事实与推断时使用：`explicit` 明确陈述、`supported_summary` 有依据的概括、`inference` 模型推断、`uncertain` 无法确认。推断不能冒充原文事实 |
| 空值和缺项 | LLM 说明 | 无依据时不补常识。只对影响理解、学习或执行的缺口写 G8，不为每个空选填字段增加一条问题 |
| 证据摘录、引用哈希 | 程序生成 | 根据实际位置取出原文片段；公开版本再脱敏。无需模型重复抄写大量原文来“证明读过” |

明确区分两类 ID：原文段落、章节和资产 ID 由程序提供；`S1` 等学习单元局部 ID 可以由模型按本篇内容分配，程序负责最终命名空间和跨文件唯一性。

## 5. 所有需要 LLM 提供的字段

### G1：材料判断、基本信息与适用人群

对应现有第一轮的材料判断和画像基本信息。原始专业／学历是来源事实，适用人群和最终投递专业是不同判断。

沿用现有材料范围：论文正文、设计说明书按正文流程处理；查重报告、开题报告、任务书等按既定规则排除。依据实际内容判断，不只看文件名。被排除或暂无法判断的正文不继续生成完整画像、脱敏、切片和入库；本次已提供附件仍独立判断，不随正文一起排除。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G1_material_basic.material_type` | 字符串 | 论文正文、设计说明书、图纸、代码／软件资料、数据等实际材料类型 | 每项材料 |
| `G1_material_basic.keep_or_not` | 枚举 | `keep`、`exclude`、`uncertain` | 每项材料 |
| `G1_material_basic.keep_reason` | 字符串 | 根据实际读取内容说明保留、排除或待核对的理由 | 每项材料；缺少关键读取内容不能直接判无用 |
| `G1_material_basic.real_title` | 字符串或 null | 原稿真实题名；身份信息的公开处理由 G7 指示 | 原稿有正式题名时 |
| `G1_material_basic.title_source_refs` | 引用数组 | 题名来自何处，避免把文件名当正式题名 | 能定位时 |
| `G1_material_basic.original_major_degree.major_raw` | 字符串或 null | 原作者专业的原文表述 | 明确记载时 |
| `G1_material_basic.original_major_degree.degree_level` | 字符串或 null | 原始学历层次 | 明确记载时，不按文风猜测 |
| `G1_material_basic.original_major_degree.degree_type/study_form` | 字符串或 null | 学位类别、学习形式 | 明确记载且对使用有价值时 |
| `G1_material_basic.paper_type` | 字符串或 null | 原稿属于毕业论文、设计说明等什么类别 | 按证据填写 |
| `G1_material_basic.audience_fit[]` | 对象数组 | 各适用人群／层次的判断 | 值得保留的材料 |
| `audience_fit[].who/level/fit/reason` | 字符串 | 谁能使用、适用层次、适合程度、具体理由 | 不把适用性判断当原作者真实学历 |
| `audience_fit[].unit_ids` | ID 数组 | 哪些学习单元支撑这项适用判断 | 能对应时 |
| `G1_material_basic.research_overview` | 对象 | `question` 主要问题、`object` 研究对象、`path` 整体研究路径、`source_refs` 依据 | 保留正文，简明概括 |
| `one_line_profile` | 字符串 | 用一句话概括这篇能学习什么及关键限制 | 能概括时，不作为正文替代 |

不要求模型另建作者姓名、学号、导师、学校、教学点等身份字段。需要脱敏的身份信息只进入 G7 私有定位计划。学校／企业作为公开研究对象时按具体语境保留。

### G2：真实章节与章节功能

对应现有第一轮 Tree 要求和第二轮结构核对。完整目录由程序保留，模型重点解释其功能。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G2_chapters.annotations[].section_id` | ID 引用 | 本条解释对应的真实章节 | 沿用输入目录 ID |
| `annotations[].function` | 字符串 | 这一章实际承担什么工作 | 每个真实章节可以简述 |
| `annotations[].is_core/core_reason` | 布尔＋字符串 | 是否属于核心研究／分析／论证／设计章节及依据 | 按内容判断，不凭标题 |
| `annotations[].question` | 字符串或 null | 本章解决的问题 | 核心章节重点填写 |
| `annotations[].approach` | 字符串或 null | 如何推进研究或设计 | 核心章节重点填写 |
| `annotations[].output` | 字符串或 null | 形成的实际产出 | 核心章节重点填写 |
| `annotations[].unit_ids` | ID 数组 | 与 G3 学习单元的关联 | 能对应时 |
| `annotations[].connections[]` | 对象数组 | `to_section_id`、`relation`、`basis`：输入、承接、验证、解释等真实前后关系 | 有依据的关系，不按通用模板补链 |
| `annotations[].source_refs` | 引用数组 | 本章功能判断的来源 | 核心判断 |
| `G2_chapters.chain` | 字符串 | 简明描述文章实际研究推进顺序 | 可以从上述内容概括，不强求一条完美逻辑链 |
| `G2_chapters.breaks[]` | 对象数组 | `type`、`detail`、`source_refs`、`impact`：实际结构断点或冲突 | 影响理解时；与 G8 可互相引用，不重复长篇描述 |
| `G2_chapters.structure_corrections[]` | 对象数组 | `target_ref`、`suggested_level/parent_id`、`reason`、`source_refs`：纠正提取工具误识别的标题结构 | 仅解析目录明显错误时，不能替作者重构论文 |

示例的 `outline` 可保留为程序提供的原始目录。`chapter_function` 是上述注释的可读视图，不必让模型把相同内容输出两遍。

### G3：研究过程与后续学习单元——最需要保留的内容

对应现有第一轮研究过程、第二轮实质核对和第三轮学习切片。不能把这一组缩成“用了什么方法”的标签。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G3_research_process[].id/name` | 字符串 | 本篇局部单元 ID 和工作名称 | 每个实际研究单元；不规定固定数量 |
| `[].question` | 字符串 | 该单元解决什么问题 | 每个单元 |
| `[].method` | 字符串或数组 | 实际采用的方法、分析或设计动作 | 不能只有空泛方法名称 |
| `[].work_attribution` | 枚举 | `author_work` 作者工作、`cited_work` 引用他人工作、`mixed` 混合、`uncertain` 无法确认 | 防止把文献综述当作者实证成果 |
| `[].method_evidence` | 对象 | `status`、`detail`、`source_refs`；状态为 `documented` 原文有过程依据、`claimed_only` 只有声称、`conflict` 相互矛盾、`uncertain` 无法判断 | 特别适用于“访谈／实验／调查”只在文字中宣称的情况；有原文记录不等于真实性已独立核实 |
| `[].selection_rationale` | 字符串或 null | 原文为何采用该方法、材料或设计 | 原文交代时；不自行补“合理理由” |
| `[].materials[]` | 对象数组 | 输入材料；可以是数据、文本、案例、问卷、设计资料、代码等 | 每个单元按实际需要 |
| `materials[].id/type/description` | 字符串 | 材料局部 ID、类型和具体内容 | 有材料时 |
| `materials[].key_fields` | 数组 | 重新取材需要哪些变量、指标、文本属性或设计要素 | 原文支持时 |
| `materials[].time_scope` | 字符串或 null | 原文材料时间范围及其范例属性 | 有关时 |
| `materials[].comparison_objects` | 数组 | 比较对象、组别、案例或参照物 | 有关时 |
| `materials[].organization` | 字符串或 null | 材料如何组织：样本表、编码框架、案例对照、模块输入等 | 原文支持时 |
| `materials[].source_refs` | 引用数组 | 材料说明的原文位置 | 能定位时 |
| `[].steps[]` | 有序对象数组 | 实际操作步骤，保留原文顺序 | 核心内容，不用常识补全过程 |
| `steps[].step_id/action` | 字符串 | 步骤局部 ID、做了什么 | 每一步 |
| `steps[].input_refs/output_refs` | ID 数组 | 使用哪些材料或上一步结果，形成哪些产出 | 能建立明确关系时 |
| `steps[].source_refs` | 引用数组 | 操作的证据位置 | 关键操作 |
| `[].output[]` | 对象数组 | `id`、`type`、`content`、`source_refs`：实际形成的分析结果、模型、设计、流程或论证 | 每个单元按实际内容 |
| `[].interpretation` | 字符串或对象 | 作者如何解释这些产出、与研究问题有什么关系 | 有原文依据；模型批评放 G8 |
| `[].params[]` | 对象数组 | 关键公式、参数、单位、阈值和条件；每项含 `name`、`expression_or_value`、`unit`、`role`、`source_refs` | 影响复用方法时；不照抄所有历史数值 |
| `params[].role` | 枚举 | `method_requirement` 方法必要条件、`author_choice` 本篇选择、`uncertain` 无法确认 | 不把作者样本数／年份改写成通用要求 |
| `[].conditions` | 数组 | 原文支持的适用条件或前提 | 有则填 |
| `[].limitations` | 数组 | 该单元的局限、缺口和使用限制 | 有实质影响时 |
| `[].section_ids/asset_ids/source_refs` | 引用数组 | 涉及章节、图表和原文位置 | 跨章节单元允许关联多处 |
| `[].upstream_unit_ids` | ID 数组 | 哪些前置单元实际向本单元提供输入 | 只记录真实依赖，不另外构造知识图谱 |
| `[].flags` | 数组 | 需要注意的简短问题标记，可引用 G8 条目 | 沿用示例已有标记，避免只写标签而无解释 |

已有字符串形式的 `materials`、`steps`、`output` 可以保留内容后转换为以上对象；转换时不能凭格式要求虚构字段。缺少关键语义内容才需要定向补充。

### G4：可以借鉴什么，哪些必须重新研究

对应现有第一轮迁移边界、第二轮“作者选择不等于普遍要求”和第三轮学习内容。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G4_borrowable.methods_and_structures[].item/form` | 字符串 | 可借鉴的方法、章节组织、实施流程或图表表达及其形式 | 有实际学习价值时 |
| `[].condition` | 字符串或数组 | 借鉴前提、适用范围 | 区分原文事实与模型建议 |
| `[].unit_ids/section_ids/asset_ids` | 引用数组 | 对应具体学习单元、章节或资产 | 能对应时 |
| `[].source_refs` | 引用数组 | 支撑可迁移内容的证据 | 核心内容 |
| `G4_borrowable.original_only[].item/why` | 字符串 | 哪些年份、样本、对象、数值、案例和结论仅属于本篇，以及原因 | 影响新题迁移时 |
| `G4_borrowable.original_only[].unit_ids` | ID 数组 | 限制作用于哪些单元 | 能对应时 |
| `G4_borrowable.limits[]` | 字符串 | 整篇使用范围与限制 | 有实质限制时 |

“针对新题重新取得材料、重新分析、重新得出结论”是程序统一附加的固定规则，无需每个学习单元重复生成一大段相同声明。

### G5：图表理解、用途和保存决定

对应现有第一轮图表解释、第二轮图意核对、第三轮图表取舍。`figures[]` 和 `tables[]` 按实际资产逐项记录；分组概述可以保留作简短补充。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G5_figures_tables.figures[] / tables[]` | 对象数组 | 每个实际图表一条，不能只写“图 4.1–4.30”而不对应实际资产 | 所有已取得且需作取舍的资产 |
| `[].asset_id` | ID 引用 | 引用程序提供的真实资产 ID | 每项 |
| `[].kind` | 字符串 | 用例图、结构图、流程图、统计图、研究表格、界面截图、装饰图等实际类型 | 根据内容，不只看扩展名 |
| `[].caption` | 字符串或 null | 原图题／表题，无法自动取出时由模型识别 | 有则填，不能编造图号 |
| `[].meaning` | 字符串 | 图表表达什么关系、结构、趋势、比较或步骤 | 研究相关图表 |
| `[].serves` | 字符串 | 它服务哪个研究问题或操作环节 | 研究相关图表 |
| `[].needs[]` | 数组 | 后续重做同类图表需要重新取得哪些材料 | 有学习价值时 |
| `[].organization` | 字符串 | 材料怎样组织和展示；关键指标、单位、结构、流程关系 | 影响理解时 |
| `[].section_ids/unit_ids/source_refs` | 引用数组 | 关联章节、学习单元和原文 | 有依据就填 |
| `[].storage` | 枚举或 null | `description` 只存说明、`image` 必要原图＋说明、`omit` 省略 | 有依据作决定；必要信息未取得时为 null 并列出局部缺口，不能编造决定 |
| `[].storage_reason` | 字符串 | 为什么文字足够、为什么必须保留视觉信息，或为什么可以省略 | 逐资产明确，不给“任选一个” |
| `[].limits` | 数组 | 看不清、图题与正文冲突、只有局部信息等限制 | 有则填 |
| `[].evidence_basis` | 枚举 | `pixels` 实际图像、`table_text` 提取表格、`caption_context_only` 仅图注和上下文 | 模型声明依据；不能代替程序的实际读取记录 |

最终资产的 `description` 由程序把上述语义字段组织成检索说明。已有说明包含所需信息时直接复用，无需让模型在本次输出中再把同样的内容重写一遍。

规则：

1. 文字足以传达学习内容时采用 `description`；只有难以用文字充分替代的必要视觉信息才用 `image`。
2. 不按“所有 EMF 都留图”“截图固定只保留 3–5 张”等规则代替实际判断。按真实图意决定。
3. 依赖视觉内容的结论需要实际查看图片，不能只凭标题声称已经看过；未能读取的图片如实标记。可以先利用图注和邻近正文判断是否需要视觉读取，不能因此省掉必要的看图。
4. EMF 等格式的提取、转换、尺寸记录由程序负责。转换成功不等于模型已经理解图片。
5. `omit` 是不额外保存该资产，不授权删除原稿中的内容。完整原稿保留。
6. “原图有问题”记录为限制，不在预提取时重画原图或修正研究关系。
7. 若同一说明已包含所需语义，程序可以直接拼接或复用，不需要第三次让模型重写图表说明。

### G6：最终专业分类

对应现有第二轮分类。沿用当前 883 专业目录和每个三级专业独立知识库的规则。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G6_major_classification.routing_candidates[]` | 有序对象数组 | 最终投递专业，从最相关到较相关，最多 3 个，不凑数 | 保留正文；没有合适项可以为空 |
| `routing_candidates[].code` | 字符串 | 从程序提供的有效目录中选择的专业代码 | 模型负责选择，不能自造 |
| `routing_candidates[].reason` | 字符串 | 这个专业能借鉴哪些研究内容、方法、章节组织或图表表达 | 每个所选专业 |
| `routing_candidates[].unit_ids/source_refs` | 引用数组 | 支撑适配判断的内容 | 有依据就填 |
| `G6_major_classification.additional_related_specialties[]` | 对象数组 | 其余确实相关但不投递的专业；每项 `code`、`reason` | 可为空，与投递名单不能重复 |
| `G6_major_classification.rejected_candidates[]` | 对象数组 | 可选保留 `code`、`reason`，解释某些看似相关专业为什么不适合 | 仅需保留示例已有说明时，属于审阅备注，不当相关标签或投递目标 |

标准专业名称由程序按代码填入并校验，数据库 ID 也由程序映射。示例的 `primary`、`secondary` 可以从有序投递名单派生；`tags` 中的学历等从 G1 复用，不让模型独立输出多套相互冲突的分类。

为保持当前分类要求，不能随意把完整 883 专业候选空间缩成只按文件名挑出的几十项。若以后做候选预筛，需要验证召回并能回到完整目录；本次不改变此项规则。

### G7：脱敏计划——私有交接信息

对应现有第一轮敏感信息识别和第三轮脱敏。LLM 负责语境判断和位置建议，程序执行替换、删除、遮挡并记录实际结果。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G7_anonymization[].id` | 局部 ID | 脱敏项标识 | 每个实际处理项 |
| `[].entity_key` | 字符串 | 同一对象的局部关联标识，便于使用一致代称 | 需要跨位置对应时 |
| `[].role/risk/reason` | 字符串 | 作者、导师、受访者、私人联系方式、签名等身份语境及为何要处理 | 不因为像姓名／数字就自动删除 |
| `[].scope` | 枚举 | `source_text` 原文文本、`generated_field` 生成字段、`image` 保留图片、`metadata` 发布元数据、`filename` 公开文件名 | 每项明确作用范围 |
| `[].action` | 枚举 | `replace` 替换、`delete` 删除、`mask` 图像遮挡 | 明确的必要操作 |
| `[].replacement` | 字符串或 null | 使用的中性代称或保留角色的信息 | 替换时；同一对象一致 |
| `[].source_refs` | 精确引用数组 | 正文位置或真实表格单元格位置 | 文本操作，不能只有“封面姓名” |
| `[].expected_text` | 字符串或 null | 目标范围原文，用于程序核对匹配，属于私有原值 | 文本精确匹配需要时；不能公开索引 |
| `[].target_pointer` | 字符串或 null | 生成结果中需要处理的准确 JSON Pointer，如指向某条图表说明 | 生成字段操作；不能只检查正文 |
| `[].metadata_selector` | 对象或 null | 已验证的文件部件和属性／元素位置 | 实际发布物会携带该元数据时；无需为不上传的原稿改写属性 |
| `[].image_ref` | 对象或 null | 实际保留图片及其渲染版本引用 | 图片操作，绑定真实尺寸／版本 |
| `[].redactions[]` | 坐标对象数组 | 每项 `x0,y0,x1,y1`，对应实际像素区域 | 只在真实查看图片后填写；不能编造坐标 |
| `[].location_status/issue` | 状态＋说明 | 已定位、定位不确定或无法取得必要信息，以及具体原因 | 无法执行时局部标记，不假装处理完成 |

执行边界：

- 作者／导师身份与参考文献作者署名要分开；同名也不能全文无差别替换。
- 公开研究对象的企业、学校、机构名称按研究语境判断，不能全部清空。
- 图片只遮挡明确身份区域，不能整块遮掉研究数据、结构或必要关系。`description` 项只处理公开说明，不为了脱敏再次查看不上传的图片。
- 正文、章节标题、画像、图表说明、学习切片、公开文件名和实际上传元数据都在发布范围内。程序必须统一派生，避免只脱敏正文。
- 发现明确应处理却无法定位的内容，要标明受影响的发布项；局部执行失败不要求其他论文或其他已完成语义内容重新生成。
- G7、原始路径、身份原值和候选处理备注不得整体写进公开 `profile.json`。把对象命名为 `private` 并不能自动防止它被上传。
- 原件保留。需要处理的是发布副本；不顺带纠正论文方法、实验数据或结论。

### G8：缺项、冲突、疑问与使用限制

对应现有第一轮缺项记录、第二轮实质问题核对及第三轮局部障碍。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `G8_gaps[].id` | 局部 ID | 问题标识，供其他字段引用 | 每个实际问题 |
| `[].target` | 对象或字符串 | 影响哪个字段、章节、学习单元、图表或发布项 | 尽量精确，避免笼统“文章有问题” |
| `[].type` | 枚举 | 使用下表状态 | 每项 |
| `[].gap` | 字符串 | 具体缺少、冲突或无法确认的内容 | 每项 |
| `[].impact/use_limit` | 字符串 | 影响什么理解或学习用途，哪些结论不能据此得出 | 不能自动扩大成整篇不可用 |
| `[].needed_information` | 字符串或数组 | 需要回读什么片段、取得什么文件或补充什么信息 | 确有补充需要时 |
| `[].source_refs` | 引用数组 | 问题依据及出处 | 能定位时，批注和作者正文分开 |
| `[].claim_status` | 枚举 | 是已见事实、概括、推测还是未知 | 存在判断跳跃风险时 |

| `type` | 明确含义 |
| --- | --- |
| `not_applicable` | 该研究方式本来不需要此项 |
| `source_not_stated` | 相关内容已经取得并阅读，原文没有交代 |
| `extraction_missing` | 解析、文字识别或格式转换没有取得相关内容 |
| `not_read` | 已知存在但这次没有实际读取 |
| `uncertain` | 现有证据不足以判断 |
| `source_conflict` | 原文不同位置、图文或数据之间存在冲突 |

示例中的 `missing` 要根据来源区分；`not_executed`、`suspected_not_done` 不能仅凭没有读到记录就认定作者没有做。导师批注可记录“导师提出质疑”，不能转换成已证实的研究不端事实。

这组允许记录作者原稿的错误，但不要求预处理程序替作者修正。例如表格结论写错，应保留原文并注明限制，不能按“先修正再切片”执行。

### segmentation：模型只给有必要的语义边界

对应现有第三轮正文／学习切片。模型不输出整篇正文，不计算精确 token，也不凭空生成最终行号。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `segmentation.semantic_groups[]` | 对象数组 | 对自动切分确有帮助的语义组合，含 `source_refs`、`unit_ids`、`reason` | 可为空；不要求模型重新遍历每段做一次标注 |
| `segmentation.must_split[]` | 对象数组 | 语义上应分开的内容；含准确 `source_refs`、`split_points`、`reason` | 如一长段合写多个独立文献或步骤 |
| `must_split[].split_points[]` | 位置数组 | 程序可核验的块／句边界或文本偏移 | 不只写“按 5 个语义切” |
| `segmentation.keep_together[]` | 对象数组 | 应尽量相邻的公式与变量说明、表题与解释等，含 `source_refs`、`reason` | 建议不能凌驾于硬 token 上限 |
| `segmentation.special_cases[]` | 对象数组 | 特殊表格、跨段研究过程等，含 `source_refs`、`issue` | 有实质影响时 |

程序负责全文分块、超预算拆分和连续覆盖。G3 已经承担学习语义提取，因此不再要求模型另写一整套同义的 `learning_chunks`。程序按 G3＋G2＋G4＋G5 生成学习／图表切片，并保留来源和限制。

### attachments：已提供附件的独立判断

附件有实际输入时才填写，不把整个目录任意扩展成新任务。论文正文被排除，不等于附件也无价值。

| 字段 | 类型 | 要提取或判断什么 | 填写条件 |
| --- | --- | --- | --- |
| `attachments[].file_ref` | ID 引用 | 实际提供的附件文件 ID | 程序提供，模型引用 |
| `[].kind` | 字符串 | 图纸、程序／代码、问卷、数据、设计资料等 | 按实际内容 |
| `[].decision/reason` | 枚举＋字符串 | `keep/exclude/uncertain` 及实际依据 | 每个已提供附件；无法读取不等于无用 |
| `[].description/learning_value` | 字符串 | 附件包含什么，能用于什么学习 | 保留项 |
| `[].related_article_title/association_basis` | 字符串或 null | 能确认的论文关联线索及依据 | 不凭文件名强行建立关系 |
| `[].source_refs/limits` | 引用数组／数组 | 证据与读取、使用限制 | 按实际情况 |

独立附件不强行生成论文 Tree、全文正文切片或伪造论文内容。文件复制、格式读取记录、身份绑定和后续路由沿用既有附件机制；不能用正文模板把附件一律拒收。程序或宏文件只作资料读取，不因提取画像而执行。

## 6. 哪些字段和工作不应该交给 LLM

下列项目由提取程序、WorkBuddy 调用的本地读取工具或后续脚本产生。模型可以引用真实结果，不能自己编造。

| 程序负责的内容 | 具体字段或动作 | 作用 |
| --- | --- | --- |
| 原稿绑定 | `source_binding.source_id`、`source_sha256`、私有文件定位、输入清单 | 防止画像与其他论文串用；哈希计算针对原始文件字节 |
| 提取版本 | 原始文件哈希、提取正文哈希、索引版本／哈希 | 原稿相同不代表提取内容和偏移一定相同，三者需要分别绑定 |
| 固定规则版本 | `schema_version`、目录版本、提示词／规则版本 | 判断成果能否继续复用，不因一次普通错误重做全部内容 |
| 完整正文 | 原文文字、表格、公式及其顺序，必要的文字识别和格式转换 | 原文由程序保存，不能用画像摘要替代；读取失败要有记录 |
| 来源索引 | 真实章节／段落／表格／单元格／图片 ID、顺序和原稿位置 | 模型有现成位置可引用，无须反复读 XML 查找 |
| 原始 Tree | 标题、层级、父子关系、原始顺序和位置 | 模型补功能说明，不重造目录 |
| 图片数据 | 提取文件、源图关联、尺寸、渲染版本、哈希、读取工具回执 | 模型解释内容和选取，程序管理真实文件；“已提供给模型”也不等于理解正确 |
| 统计 | 字数、段落数、图表数、文件数 | 可以顺手核对本样例 47／46 的差异，不要求模型估数 |
| 标准名称与路由 | 根据专业代码取得标准名称和既有知识库 ID | 不让模型创造数据库或把多个三级专业合并为一个库 |
| 脱敏执行 | 定位匹配、替换、遮挡、副本生成、代称一致性、实际执行记录 | 已匹配／已处理必须由真实执行结果确认 |
| 公开字段投影 | 明确允许发布的字段，去除 G7 原值和私有来源 | 防止整份候选画像被序列化上传 |
| 正文切片 | 最终脱敏正文的范围、内容复制、精确计数 | 模型不抄写正文；不得用字符数代替 token 数 |
| 学习／图表切片及资产说明 | 将结构化语义成果组织为可检索文本，生成或复用资产 `description` | 必须实际包含材料、步骤、产出、解释、条件、限制和回读位置，无需模型重复输出同义说明 |
| 包身份和封包 | 最终全局 ID、revision、文件哈希、manifest | 模型不写“已封包”“已通过”冒充程序结果 |
| 入库与恢复 | 去重、提交、读回、版本切换、失败续传、任务状态 | 不把“MD 写完”记作“已经入库” |
| 调用和耗时记录 | 实际请求数、输入输出 token、缓存量、重试、墙钟时间 | 界面耗时不能代替真实 usage，不让模型估算实际账单 |

来源 ID、索引生成和文件绑定应优先复用旧程序／新链路已有实现。本说明没有要求为此重写文件解析器或再造调度器。

## 7. 与现有三轮的对应关系

| 当前步骤 | 原来承担的内容 | 预提取后由谁承担 |
| --- | --- | --- |
| 第一轮 | 材料筛选、真实题名、适用层次、章节功能、研究过程、迁移边界、图表解释、敏感信息和缺项 | WorkBuddy 的 G1–G5、G7–G8、附件判断；程序提供原始索引和文件事实 |
| 第二轮实质核对 | 漏关键步骤；误读公式／单位／图意；材料与任务不匹配；定位错误；他人研究归属错误；无依据补内容；把作者选择当通用要求 | 合并为主提取输出前的有限自查，保留证据和具体问题；程序核验引用和结构。一次自查不等于原来另一次模型的独立复核，质量需以原稿抽查判断 |
| 第二轮分类 | 883 专业中的最多 3 个最终投递项和其余相关项 | G6 一次完成；程序校验和映射 |
| 第三轮图表处理 | 描述／必要原图／省略的取舍 | G5 决定；程序复制必要资产 |
| 第三轮脱敏 | 身份语境判断、公开文字与必要图片处理 | G7 判断和定位；程序实际执行、核验并生成公开成果 |
| 第三轮切片 | 正文范围、学习内容、图表关联 | segmentation 提供必要语义建议；程序从原稿及 G2–G5 构造最终切片并精确检查 |

图表取舍 → 脱敏 → 最终切片的依赖顺序仍然保留。改变的是任务分工和是否重复调用模型，不是把这些质量要求删掉。

## 8. 后续程序怎样复用，不再重读做画像

建议后续按下面的顺序衔接；这份说明没有实现这些连接：

1. 找到某篇的候选 MD，读取唯一 JSON 数据块，核对原稿身份、哈希、索引和格式版本。
2. 复用完整正文和资产；若只有原稿，使用现成解析能力补出正文和索引。执行信息不足时列出具体缺项，不能自动改走三轮全文重跑。
3. 将 G1／G3／G4／G6／G8 映射到公开 `profile.json`，将真实目录＋G2 注释映射到 `tree.json`，将 G5 映射到 `assets.json`。
4. 按 G7 生成发布副本，处理实际会上传的正文、画像、标题、资产说明、文件名和必要图片；私有原值不进入发布包。
5. 按最终正文生成 `article.redacted.md` 和正文切片。确需在长段内部换行时，程序在形成最终行号前作可追溯的结构化分行，保持文字和顺序；不能伪造最终行号或删改内容来通过。
6. 根据 G3 以及关联的 G2／G4／G5 生成 `learning`／必要的 `chart` 切片。内容要包含实际学习过程，不能只写一个方法名或单元标题。
7. 复用当前 token 精确检查：实际 embedding 输入含其前缀等内容，模型 tokenizer 不超过 2000 tokens；native 内容路径 cl100k 不超过 2038 tokens。超长由程序有边界地拆分，不让模型重写全文。
8. 核验两层覆盖：一是提取正文对原稿的读取情况、失败页／表／图记录；二是最终正文切片从首行到末行连续、不重叠、不遗漏。第二层通过不能证明第一层没有漏读。
9. 复用既有投递、去重、读回和版本记录。上传的是公开正文／画像／切片／必要资产，不是原样上传私有候选 MD，也不把摘要作为整篇正文上传。

**当前缺口是候选格式的导入与映射，而不是缺一套新的预处理工作台。** 现有 `package.py` 已能按最终行范围复制正文、检查路由和封包；它不等于已经支持读取这份 G1–G8 的 MD。程序生成切片边界和学习切片的连接也需要落实。

还有两个已经在现有代码中核实的要点：

- `rag.py` 对画像只取部分字段作索引，学习单元索引也只含标题、方法、位置等少数字段。完整字段留在 JSON 里，不等于材料、操作、产出和解释都进入了检索切片。
- `rag.py` 会把完整发布 `profile/tree/assets` 写入元数据。因此必须先生成经过脱敏与字段筛选的公开版本，不能把含 G7 身份原值的候选 JSON 原样交进去。

单篇独立保存便于失败续跑，也可以让不同论文并发处理。它不会自动修复并发调度、限流、数据库锁或上传队列故障；这些属于程序执行层，不能单靠字段清单保证。

## 10. 定稿时只检查真正影响使用的事项

第一篇无需达到“论文毫无缺点”，只需确认下面这些关键事项。普通格式差异、措辞和非关键空项不应触发整篇重跑。

| 检查 | 目的 | 失败后的处理范围 |
| --- | --- | --- |
| MD 数据块可解析，能够绑定正确原稿 | 程序可以直接消费，不再靠 LLM 读报告 | 修格式或绑定，不重做已有语义内容 |
| G3 能回答材料、步骤、产出、解释，且能回读证据 | 保留画像的实际学习价值 | 只补缺失的单元或关键字段 |
| 图表取舍明确，必要图像能找到 | 发布决定可执行 | 只处理对应资产；不能因图数不一致直接断言漏图 |
| 脱敏计划可执行，公开成果不带私有原值 | 正文以外的画像、说明和元数据也得到处理 | 修对应位置和公开字段映射 |
| 原稿读取情况有记录，最终正文切片覆盖与预算通过 | 避免漏正文和非法切片 | 重做对应提取或切片范围，不重做画像 |
| G3 内容确实进入学习切片和读回内容 | 防止“字段齐全但 Agent 学不到” | 修字段映射和渲染，不让模型重读全文 |
| 专业代码与目录一致，路由符合最终分类结果及已授权投递范围 | 防止错误入库对象；不增加逐篇人工审批 | 修该篇分类或映射，不扩成全库重分类 |

对原稿做有限抽查可以发现内容偏差，但 JSON 校验、引用存在和脱敏替换成功，都不能单独证明语义完全准确或没有漏识别的隐私。本方案不增加固定评分表，也不要求每个小缺项触发模型复核。
