# 大小工单四窗口并行实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement your assigned tasks. Preserve the user's chosen four-chat execution method.

**Goal:** 按已确认的业务规则实现新任务的原生 Prefect 大小工单链路，并与既有前端候选接通。

**Architecture:** 用户已建立四个工作窗口，另由当前调度窗口协调。窗口一负责工单、生命周期、准入、服务器凭据及 API；窗口二负责逐篇处理；窗口三负责正式入库归档清理；窗口四负责前端及联调。调度窗口不改业务代码。

**Tech Stack:** Python、现有 Prefect 3.9.0、现有 API/存储组件、原生 HTML/JavaScript。

**Spec:** `docs/superpowers/specs/2026-11-02-parent-child-orders.md`

**Acceptance:** `docs/大小工单改造-任务验收标准与验收记录-20261102.md`。G01要求通用全链路真正接通，按 A01～A27、E01～E06 交接实施证据；真实业务验收由用户负责，当前未验收。

## Review Focus

1. 原生子流程不能 reschedule suspend：工单窗口验证父子身份、暂停及恢复。
2. 资源等待期间父工单暂停：工单窗口和阶段窗口验证发送前再次准入。
3. 模型请求结果未知或保存中暂停：阶段窗口验证不重发、允许保存已发结果。
4. 三库部分成功与附件失败：入库窗口验证只补失败库、未全成功禁止清理。
5. 来源目录混有异常文件：入库窗口验证只删该篇明确清单，杂物和共享数据保留。
