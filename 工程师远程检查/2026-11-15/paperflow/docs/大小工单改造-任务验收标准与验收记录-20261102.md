# 大小工单改造：任务验收标准与验收记录

版本：2026-11-02，按调度聊天已确认的第 1～27 条需求及后续分工整理。

补充定案：所有改动面向通用业务规则；专业排名统一属于整篇论文；暂停按最后准入判定，已获准单次请求可发出并收尾，不增加额外同步。

最新补充：用户要求“自检出现问题，然后自动修复”。已识别且有对应现成启动入口的依赖未启动，由自检自动恢复并复检；未知原因或恢复失败仍需显示具体问题并阻止创建。这不改变工单手动开始和业务失败手动恢复的规则。

**本文规定预期结果，不代表已经实现或已经验收。最终验收由用户逐项确认。**

候选开发和隔离联调现已汇入 `docs/大小工单改造-交付与逐项验收报告-20261102.md`；统一启动命令、实际加载状态、检查范围和逐项操作以该报告为准。业务预期以本标准最新补充为准，所有用户结论仍待验收。

## 使用方法

1. 四个窗口按对应编号实施，并在交接中逐条给出代码位置、检查结果、未完成部分。
2. 调度窗口汇总为最终验收报告，再通知用户开始逐项验收；未实现或有阻塞的项目必须明确列出，不能宣布“全部做好”。
3. 开发阶段可以用合成资料、临时目录和隔离服务检查。真实论文处理、正式库写入、NAS 写入、来源删除和最终业务验收由用户安排。
4. 每项分别记录“候选修改完成”“隔离检查通过”“验收版本已加载”“用户验收通过”。前一项不能替代后一项。
5. 本文没有规定的业务规则不能由各窗口自行扩展。需求变动由调度窗口向用户确认，再同步同一版本。

窗口简称：W1＝1 梳理工单与控制；W2＝2 逐篇处理全流程；W3＝3 梳理入库、归档与清理；W4＝4.前后端联调与整体验收。调度窗口只负责协调、核对和汇总。

## 总验收门槛 G01：通用链路完整贯通

用户再次明确：当前测试资料只是用来验证整体流程，最终目标是整个链路完整跑通。

验收从用户正常选择资料、新建任务开始，按同一实际调用链完成：

**依赖自检 → 大工单保存 → 分类与资料交付 → 原生论文小工单登记 → 前处理 → LLM及全文专业判定 → 后处理 → 所选正式RAG库全部入库 → 一份NAS原文附件归档 → 本机该篇清理 → 小工单及大工单按条件完成。**

必须同时满足：

- 各模块已接入同一实际入口、同一套工单身份和真实处理清单，前端控制与显示对应这条链；不得需要人工改库、补回执、改状态、重启旧消费者或逐阶段手工接线才能走通。
- 用户提供的测试资料用来验证这条通用链；换一批符合要求的资料仍使用相同业务规则。遇到失败、未识别或结果未知，按既定规则停住、保留和恢复，不能为追求全部绿色而跳过问题。
- 模块单测、合成响应、替身服务器和单阶段成功都是开发证据，不能代替实际链路接通与用户全流程验收。交付时仍存在占位返回、恒定未就绪、自检假通过、未调用的适配器、缺失阶段或仅模拟数据，则整体未完成。
- 调度完成收口后，报告必须给出统一验收入口、实际候选版本/加载状态、每一步可观察结果及其Prefect/服务器证据；用户亲自运行并逐项确认，开发窗口不得提前勾选通过。

G01是最终交付门槛，下面A01～A27是这条链上的具体规则，E01～E06是实现边界。

## 实现质量及范围标准

| 编号 | 所有窗口必须满足的预期结果 | 调度核对方式 |
| --- | --- | --- |
| E01 | 不为“理论上更稳”添加低概率边界处理、锁或复杂并发防御；确需增加时，先说明具体情景和概率依据，再获得用户确认。 | 交接标出新增防御及理由；没有必要性证据的扩展不能藏在实现中。A02已明确要求的暂停准入属于功能需求。 |
| E02 | 外部数据在入口校验一次；内部按确定类型/结构流转，不逐层重复校验同一事实。 | 核对入口与内部调用，不能用重复校验掩盖不明确的数据结构。 |
| E03 | 单次使用逻辑就近实现，不提前制造通用框架、无意义helper或多层转接。 | 交接说明复用原脚本和必需适配，未接通的占位框架不能算完成。 |
| E04 | 非必要不用try/catch；可以清楚写在一个函数中的逻辑不硬拆。 | 只保留实际需要的错误边界，不能吞异常后返回假成功或假零。 |
| E05 | 各窗口只修改负责模块；确定事项推进，业务或范围不确定事项先交调度向用户确认。 | 文件清单和职责对照；接口提案不能冒充已确认API，模块交接不能互相修改对方文件。 |
| E06 | 所有修改修复一类业务问题，形成对不同论文都适用的规则；不为当前任务、某篇文件名、论文ID、测试编号或特定内容添加通过分支，不为让样本通过而放宽原定判断。 | 每项修改说明适用的输入类别和统一行为；用有代表性的不同材料/状态验证，既检查应通过的情况，也保留应失败、未识别及待核对的情况。真实配置中的正式库映射不属于测试特例。继续遵守E01～E04，不把通用性变成提前抽象或范围扩张。 |

## 不擅自扩展的事项

- 本次27项问答没有定义“删除整个任务”按钮的新语义。不得把逐篇成功后的自动清理，擅自等同于删除任务时可删除未归档原文。

- 接口路径、函数签名和存储实现由对应窗口依据真实代码核查；若影响上述业务结果，须先向用户说明，不静默降低标准。
