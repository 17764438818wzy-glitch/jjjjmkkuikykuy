# 上游附件判断与第四状态的 MD 交付口径

状态：本窗口根据用户确认的存储方案整理的接口约定，尚未代表上游窗口已完成接入。

用户澄清：“颗粒度对齐”主要指像正文画像一样，固定每个附件交付的 MD 文档格式，让上游知道交什么、第四状态知道如何存。以下以“原附件文件 + 一份标准 MD”作为正式交付单元。字段和模板是本窗口拟定的 v1 草案，尚未宣称两端代码已支持。

模板：`../../templates/附件交付模板_v1.md`。示例：`../../examples/附件交付示例_v1.md`。

## 每个附件实际交付什么

```text
<论文编号>/attachments/<附件编号>/
    original/<原附件文件，例如 项目源码.rar>
    attachment.md
```

一个原附件对应一份 MD。三个原附件就是三组交付；一个压缩包仍然只是一组，不要求包内每个文件再写 MD。原件单独放在 original/ 中，即使原文件本身叫 attachment.md，也不会与交付说明重名。全篇没有附件时交付空附件清单，不生成虚构的附件卡。

上图是打包示例，不要求每次更新 MD 都复制一份原件。上游也可以保留原件，用不可变版本目录保存 MD，再通过程序记录绑定两者路径和哈希。第四状态消费冻结的具体版本；仅修改说明不能更换原附件身份或重复上传原件。

MD 采用固定模板版本、固定标题和固定字段。开头元数据由程序填写身份和文件事实；后面的简短正文复用已有附件判断，目录也由程序生成。内部可以继续保留现有 JSON 缓存，正式对接无需再提供一套内容重复的 JSON 说明，更不需要追加模型调用来把 JSON 改写为 MD。

附件类型、简单说明、判断依据及限制必须来自第三状态附件意图识别 LLM 的完整可核验结果；同一附件已有成功结果可以复用。Nimble 分流标签或程序文件类型判断不能代替该识别结果。程序只补身份和目录、保留实际读取范围，再确定性渲染为一份完整 MD。`description.json`、原回答和请求台账留在第三状态内部追溯；`delivery.json` 可以作为路径、版本及哈希的运输记录，不作为另一份业务说明必填交付。

## MD 固定内容

| 部分 | 内容与责任 |
| --- | --- |
| 文件身份 | 模板版本、论文编号、附件编号、原文件名、格式、字节数、SHA256；由程序填写，与原件核对 |
| 附件类型 | 简单类型；复用附件判断，不能判断时写“未确定” |
| 简单说明 | 一两句话；说清是什么、大致用途，有依据时说明与正文的关系；不要求研究画像 |
| 读取依据与限制 | 实际看过什么、依据来自哪里、哪些内容未读或不能确认 |
| 包内目录 | 压缩包的目录状态、总数、已列数及相对路径/类型/大小表；非压缩包明确写不适用 |

元数据字段名及章节标题以模板为准。程序能够从固定结构取得身份和目录事实，存储阶段不再调用模型理解自由格式说明。

模板中的占位符必须替换。身份和哈希缺失或与原件不符时，不接收入库；语义无法确认可以如实写“未确定”。目录未读取、读取失败和目录为空分别表达。示例仅演示格式，不能当成真实可入库成果。

附件 MD 不要求上游填写 RAG 库 ID、远端文件 ID、下载链接、上传状态或 NAS 回执。这些由第四、第五状态产生；正文专业顺序继续来自正文画像。第四状态保留原始交付 MD，在发布的说明/引用和入库回执中补充实际存放位置与下载入口。

用户确认：上游只交付正文与正文画像、附件与附件简单标识两类材料。附件原件只在正文最高关联专业的附件库保留一份，其他命中专业引用该原件；需要时提供下载能力，让消费方自行下载查看。当前运行任务不改动。

## 颗粒度

- 一个原始附件文件对应一个附件编号。一个 RAR/ZIP 算一个附件；里面的成员只是该附件的目录条目，不自动拆成多份独立附件。
- 简单说明只回答“这是什么、大致用于什么、实际看到了什么”。复用已有判断，一两句话；不能由文件名推断已验证的功能，也不新增正文画像、专业判断或逐文件模型分析。
- 包内目录由程序读取，模型不负责列目录。列出相对路径、文件/目录类型及可得的大小，不执行或展开运行程序，不宣称目录中的文件内容已被理解。
- 专业归属沿用正文画像的已确定排序。第四状态不为附件或包内成员重新调用模型判断专业。

## 上游交付

现有 `description.json` 可以继续作为内部结果，字段 `paper_id`、`attachment_id`、`source_sha256`、`format`、`kind`、`summary`、`evidence_refs`、`limitations` 渲染到 MD 对应位置。原文件名和大小从冻结清单取得。不能要求模型重新生成程序已有的编号、哈希和文件事实。

目录直接纳入 MD 的固定章节，至少包含以下信息；表内英文字段用于说明含义，MD 的实际字段名及呈现方式以模板为准：

| 字段 | 含义 |
| --- | --- |
| `source_sha256` | 与原附件一致的 SHA256；不能拿另一个包的目录配此附件 |
| `listing_status` | `complete` 完整列出、`partial` 仅列一部分、`unavailable` 无可交付目录、`not_archive` 非压缩包、`not_read` 有依据确认未尝试读取目录 |
| `entries` | 条目列表：相对路径、条目类型、可得的大小；不是完整文件内容 |
| `listed_entries` | MD 表格实际数据行数；上游未知类型条目不进入表格，仍保留在原证据中 |
| `total_entries` | 可靠的原目录总条目数；无法确定时为 null，不能填 0；过滤未核实条目不能抹去已知总数 |
| `reason` | 截断、加密、损坏、不支持格式或尚未生成等原因 |

上游沿用当前 2000 条的有界目录原则时，超过限制应明确标为 partial，并报告实际列出数量。正文/README 等内容预览与目录字段分开；不能把混有 README、已被 24000 字截断的 text 当成完整目录。

“完整目录为空”必须是成功读取后的确证。缺字段、打不开、加密或尚未处理均不能当作空附件或空压缩包。

目录状态按证据区分：`not_read` 仅用于有依据确认从未尝试读取目录；已经读取但未留存目录，或无法确认历史是否读取过，均使用 `unavailable`，并在原因中明确区分。仅缺少已保存的结构化目录，不能推断为未读。

## 字符编码与解析

正文内联文本和目录单元格先将原始 `%` 编为 `%25`，再将 CR 编为 `%0D`、LF 编为 `%0A`；随后按 HTML 规则转义 `&`、`<`、`>`，最后将竖线、反斜杠、反引号、星号、下划线、方括号和井号编为十进制字符实体，例如竖线写为 `&#124;`。这样每个目录条目仍只占一行，原文件名中的 Markdown 字符保持字面含义。

消费者从 MD 原始文本取得单元格后，先且仅执行一次 HTML unescape，再且仅执行一次 percent unquote；不得循环解码，也不得从已被 Markdown 渲染器解码的文本重复解码。原始字面量 `%0A` 应编码为 `%250A`，读回仍是字面量 `%0A`，不能变成换行；原始字面量 `&#124;` 与真正的竖线也必须可区分。

开头元数据采用 JSON 标量序列化，字符串和整数保持类型；不套用正文的 HTML/percent 解码规则。身份字段与冻结清单和原件哈希核对。固定章节标题、目录标签及 `complete/partial/unavailable/not_archive/not_read` 状态值保持不变。

## 第四状态消费

只核验原附件身份、接收已有简单说明和目录结果、保存原件、建立可检索说明与跨专业引用、提供原件下载及读回校验。RAR 保持原包；目录缺失或不完整时，保存真实读取状态，不重调模型补做附件判断，不声称已读包内文件。

NAS 继续保留原稿和原始附件，解压成员不因生成目录而变成长期归档副本。本轮不增加自动下载后的深读或执行行为。

## 已核实的接口差距

第四状态候选中仍沿用的适配层 `attachments.py`：

- `description.json` 已有简单说明、证据引用、限制及论文/附件/源哈希身份。
- ZIP 目录当前混在 `evidence.json.text` 中，最多 2000 条，并可能再次受 24000 字截断；不能保证结构化完整目录。
- RAR 当前退回文件事实识别，未读取包内目录。

第三状态候选 `stage3-h21-20261028/paperflow_prefect/attachment_card.py` 已提供确定性 MD 生成函数，身份字段和固定章节已与模板对照。第四状态尚无可交付的 MD 校验/消费函数；本次格式核对不代表两端接入或真实入库验收通过。不得通过猜测旧 text 或重新调用模型来掩盖该缺口。旧产物转换保留原始说明及依据：有依据确认未尝试读取目录才用 `not_read`；读过但未留存，或历史是否读过未知，均用 `unavailable` 并说明原因。已有旧文本预览据实写入读取依据，不另造状态值，也不能据此标成 complete。

## 对齐验收

1. 普通文件：说明可用，目录标 not_archive。
2. 正常 RAR/ZIP：一个附件编号，目录条目与原包绑定，可下载原包。
3. 超限包：partial，列出数量和总数口径准确。
4. 加密/损坏/不支持的包：保留原件和原因，可下载，不标已解析。
5. 旧说明无目录：确知未尝试读取时用 not_read；读过但未留存或历史读取情况未知时用 unavailable 并写原因，不把缺失字段当空包。
6. 三个相关专业：只上传一份原件，其余条目引用相同附件身份及下载入口。
7. 第四状态和恢复流程不调用上游附件判断或正文画像模型。
8. 每个原附件与 MD 一一对应，模板版本可识别，论文/附件编号与文件哈希一致；错误配对、占位符和缺失必填身份不能入库。
9. 从现有说明生成 MD 采用确定性程序渲染，模型调用增量为 0；渲染不改变原判断及读取限制。
10. 含字面量 %0A、真实换行、竖线、HTML 实体字面量和 Markdown 特殊字符的相对路径，按约定各解码一次后与原路径相同；元数据身份不经此解码。
