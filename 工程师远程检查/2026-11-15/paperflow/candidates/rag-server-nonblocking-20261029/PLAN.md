# RAG 入库接口解除阻塞实施计划

> 实施范围：用户已选择的第一步。只在隔离副本实现和验证；当前任务、服务、20 路配置和真实数据保持不变。

**目标**：入库的同步工作等待时，Quart 事件循环仍可处理轻量请求；并发资源有上限，保留现有请求、切片、可见性和返回契约。

**基线**：`baseline/snapshot.json` 固定 2026-10-29 正在运行容器的文件哈希、Python 3.13.11、Quart 0.20.0。候选修改 `chunk_api.py` 和 `rag/utils/es_conn.py`；保留原始文件和逐行差异。复用现有 `ContextVar` 用户标识、Peewee 原子计数和 ES 客户端。普通 `thread_pool_exec` 的临时池在取消时会同步等待关闭，不能用于此处；不占用已有清理线程池。

**隔离约束**：不重启或切换当前服务、不调整现有并发/队列、不访问真实写入端、不调用画像模型、不上传真实资料。验收使用本地 Quart 路由和临时数据库、模拟向量与 ES 外部边界。候选完成不等于已部署或真实提速。

**初始设计**：保留原权限检查顺序与 API 格式，把认证后的业务同步阶段交给独立的、最多 4 个线程的共享执行池；每次传递独立上下文。请求取消后已开始的线程可能继续运行，恢复仍按已有回执先回查，禁止盲目重发。

**复核后的调整**：完整线程化候选 `candidate` 在最终重查后、ES 提交前仍可能与禁用/删除交错，不能上线。`candidate-embedding-only` 只把权限初查和向量客户端构造、计算移到线程池；其后的权限重查、图片、ES 和计数在事件循环上同步执行。它仅缓解向量等待；ES 写入阻塞以及后台线程/其它进程的并发边界仍未解决，亦不能上线。ES 客户端增加默认兼容的严格选项，仅本接口关闭未知写入重试；它不使 ES 和 SQL 变成同一事务。

**任务**：

- [x] 独立复核完整线程化方案，并以反例确认其最终写入竞态。
- [x] 制作仅解除向量等待的保守候选，验证线程上限、上下文、取消、身份、可见性、图片及已知 ES 错误。
- [x] 核对桌面既有未知结果恢复逻辑，使用隔离本地测试验证不重新上传/调用画像模型。
- [x] 使用一次性本地 MySQL 验证原生数据库锁的跨进程行为、连接池复用和连接断开。
- [x] 以独立实验验证持久写入意图、未知状态和旧变更重放保护；该实验尚未连接真实服务。
- [ ] 解决 ES 写入阻塞，并建立跨线程、跨进程的文档变更与未知写入安全边界。
- [ ] 贯通真实的操作终态查询和恢复，不以一次读回代替原服务端写入结束。

**停止条件**：发现改造无法在不扩大变更范围的前提下保持权限/上下文/数据边界；同一验收问题两轮修复无改善；或任何验证必须接触真实业务数据时，保留已完成证据并报告。
