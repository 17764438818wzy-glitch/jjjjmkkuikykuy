# RAG 服务端三步优化：本地候选验证与未完成项

## 当前结论

三步已有隔离候选与本地测试，**尚未完成生产接线和验收，不得部署**。当前任务、真实服务、Prefect 配置及并发额度没有被修改或重启；没有向真实 RAG 写入，没有调用真实模型，也没有操作真实 NAS 或原始论文。

新候选的 `completed` 只证明该候选收到了匹配的写入应答，且文档／知识库计数和操作终态已在同一 MySQL 事务中提交。它不是论文全文读回、检索通过、整篇交付或者 NAS 归档完成的证明。

## 本轮实现与本地验证

1. **解除事件循环阻塞**：候选用有界线程池执行同步工作，分别试验每进程 2 和 4 个工作单元；同时分别记录执行、池内等待、准入前等待。准入前等待也有上限，超出时在建账和工作提交前拒绝。模拟 20 个请求时健康检查仍能响应；运行中请求取消不会提前释放线程名额。
2. **批量向量**：候选调用既有多文本向量接口，按正文直传接口的 `0.1 × 标题 + 0.9 × 内容或问题` 组合，支持按 8 或 16 个切片及输入 token 预算分组。与从本地快照提取的原单片接口在确定性假模型下逐项比对；没有调用实际 Ollama 或 GPU，也没有证明实际吞吐或真实向量数值一致。
3. **ES 批量**：候选将同一篇最多 16 个切片合并提交，保留 `refresh=wait_for`，核对每项的索引、切片身份及结果。使用真实 Python ES 客户端访问环回地址上的模拟 HTTP 服务，验证了一批一次提交及参数。部分成功单独保存每项状态；超时或应答不完整保持未知且不自动重发。未测试真实 ES 持久化或检索。
4. **去重、恢复和计数**：按数据集、文档、切片和内容／请求摘要保存原操作身份。单条与批量交错、同批并发及重叠批次测试不会重复调用假模型或发送；已确认写入而计数事务失败时，只补计数。模型返回的已知用量在 ES 发送前保存；无法确认的用量保持未知。局部失败或未知写入仍保守停住，并非已实现完整自动恢复。
5. **第四到第五状态**：现有项目的四项本地测试验证了模拟的 20 路共享额度、空附件不申请 RAG 槽、较快论文不等待另一篇即可进入归档，以及临时目录中的正文和附件复制核验。它们不是新服务端候选到真实 Prefect／RAG／NAS 的端到端接线，也不证明生产全局额度或实时任务状态。

## 本地测试证据

- `evidence/final-candidate-suite.log`：候选 81 项通过，含两条现有 Pydantic 兼容性弃用提醒；使用一次性本地 MySQL、模拟模型、环回模拟 ES 及合成数据。
- `evidence/batch-4worker-repeat.log`：针对本轮曾复现的批量 MySQL 锁冲突，4 工作单元／16 片组合另外重复三次通过。此前反例保存在 `evidence/batch-integrated-lock-failure.log`。
- `evidence/stage45-existing-tests.log`：现有项目四项相关模拟测试通过。
- 临时 MySQL 按本实验的目录及端口退出；最终本机核对本实验实例数为 0。
- 测试时发现已知模型用量未在 ES 超时后保存和批次成员范围锁冲突，已补反例并修复；`evidence/model-usage-red.log`、`evidence/batch-integrated-initial-failure.log` 保留修复前证据。

## 尚未完成，禁止作为上线依据

- 新单条／批量逻辑和操作终态查询没有接入真实 RAGFlow 路由；新模型表和字段没有迁移，真实鉴权、线程内模型实例构造及现有调用方兼容性未联验。
- 原有切片修改、文档启停／删除、权限变更、后台执行器等路径没有接入同一持久化并发门禁。单独开启新入口仍可能与旧路径竞争，导致残留切片、状态不一致或权限变化竞态。
- 客户端的终态保护仍是隔离候选；原生批量回执当前会保守停在待核对。进程崩溃、未知写入、批量部分成功和权限变化后没有完整的自动恢复协议。
- 必须在与真实业务完全隔离的完整环境中验证真实模型、ES、读回和检索、权限与删除交错、网络故障、跨进程限流及逐篇 NAS；之后才能讨论实际接线和分阶段实测。
- 这里的 2／4 是每进程工作单元上限，不是 Prefect 全局 20 路；尚无真实吞吐或超时率数据支持把当前 20 路改成 40 路。
