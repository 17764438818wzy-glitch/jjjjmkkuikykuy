# RAG 服务端第一步：隔离验证记录

> 本文件保留较早一轮的历史结论；后续三步候选与最新本地验证见 `ACCEPTANCE-20261029-CONTINUED.md`。两份记录均不构成部署或生产验收。

## 结论

第一步尚未完整达到可上线验收。向量等待的局部候选、严格处理未知 ES 写入的候选和持久写入意图实验均已保存在本目录，**均不得部署**。完整线程化候选存在文档禁用／删除时残留切片的反例；局部候选仍会在 ES 写入时阻塞事件循环，也未解决后台线程和其他进程的竞争。一次读回不能证明原服务端写入已经结束。

本次没有改动、重启或切换当前真实任务、服务及并发配置，没有向真实 RAG 库上传论文，没有请求画像模型或操作 NAS。曾对运行容器做一次只读源码快照；其来源和文件哈希见 `baseline/snapshot.json`。本地测试使用临时数据、模拟向量／ES 和一次性本地 MySQL。测试过程中有临时 MySQL 实例未自动退出，已逐一核对各自临时数据目录后关闭，测试清理已修复；最终核对没有遗留本实验实例。

## 已完成和验证范围

- 使用 Python 3.13.11、Quart 0.20.0 的隔离环境测试了局部候选：向量计算等待时，轻量请求可以响应；20 个模拟请求受 4 个候选工作线程限制，取消请求后已开始的工作仍占用线程直到结束。它不代表正式客户端 20 路已经贯通，也没有调整为 40 路。
- 保留原始切片 ID、用户上下文及原有接口结构；模拟测试覆盖切片内容、向量、图片和计数。该测试从源码提取业务函数运行，认证装饰器及真实外部服务不在范围内。
- 在候选中，ES 明确报告写入错误时不增加计数；指定的切片写入关闭自身和 ES 客户端对未知结果的自动重试。独立回环 HTTP 测试确认遇到 503 只发一次请求。超时仍可能已经写入，不能视为失败或自动重发；ES 与 SQL 也并非一个事务。
- 重跑既有发送端恢复及附件说明的模拟测试：**9 项通过**。覆盖已有写入意图但未读回时不重发、原文档身份不变、不调用画像模型等已列明情形；这不是对真实 RAG 或所有未决写入的端到端证明。
- 使用本地 MySQL 8.0.46、Peewee 连接池和运行版快照中的 `MysqlDatabaseLock` 做隔离实验：原生锁能跨进程互斥，但连接归还池后可能被另一线程取走，连接断开会失锁。不能将该锁直接套在现有服务函数外。
- 持久意图实验在独立数据库中覆盖并发写入、写入未知、写入进程退出、旧变更重放、切片身份和内容绑定，以及自动提交连接上的事务竞争。实验遇到过首次并发建行的死锁和自动提交的行锁提前释放，已在实验中修正并留下反例日志。实验尚未接入真实 RAGFlow。

## 本地测试结果

最终隔离套件：**30 项通过、4 项预期失败**。这 4 项是尚未达到的要求，不计作通过：

1. 局部候选的 ES 写入等待仍阻塞事件循环。
2. 后台线程禁用文档时，仍可出现可见切片。
3. 后台线程删除文档时，仍可出现切片残留。
4. 模拟服务端写入尚未结束时，现有恢复在切片可读后仍可能启用文档。

完整线程化候选在模拟普通接口禁用和删除交错时另外复现 **2 项失败**。详见 `evidence/full-offload-concurrency-red.log`。这些反例均为本地模拟，不是对运行中数据现状的断言。

本地 20 请求示意基准设置为向量单槽、每次模拟等待 0.10 秒、ES 模拟等待 0.06 秒：原版两次为 3.322 / 3.324 秒，局部候选为 2.090 / 2.094 秒。**这些只是模拟时间，不能推算真实服务器吞吐，也不能据此决定 40 路。**

## 尚需完成

- 为真实切片写入、文档启用／禁用、删除、后台切片变更和相关权限变更建立共同的并发边界；单独修改上传接口或使用现有连接锁不够。
- 将原服务端操作身份、内容身份、SQL 计数和操作终态可靠绑定；未知写入及变更必须保持待核对，不能凭一次读回就宣称原操作结束，也不能盲目重发。
- 接入客户端的操作终态查询与恢复协议，明确进程退出、连接断开、ES 延迟落盘及不可自动判定结果的处理。
- 在与真实业务隔离的完整 MySQL、ES 和模型提供方环境中做并发、取消、超时、权限与读回验证；仅在验证通过且不影响当前任务的前提下，才考虑后续接线与分阶段实测。
