## 统一设计

第四步复用正文原封包和回执，将正文画像、必要图表及附件说明入库并核验。每个附件按“一个原件加一份 MD”交付；原件只存最高关联专业的附件库，其他专业的说明引用同一原件，用户可下载。

整篇 RAG 核验后立即按篇交给第五步。NAS 保存正文和原始附件，完整读回并落盘回执后，才清理本地原件和已证明可清理的中间产物。最终 MD、模型请求与回答、原封包、回执和恢复日志保留。

前端分别展示排队、名额占用、真实上传、等待核验、正在核验、RAG 已核验、NAS 已核验和本地清理状态。Prefect 的 Running 或 Completed 不能直接代替这些业务结果。

## 本次观察

本次只读观察时，主 `config.json` 的 `limits.rag=4`，Prefect 服务 `http://192.168.1.120:4200/api` 的 `paperflow-connected-rag` 全局额度也为 4、占用为 0。20 是要统一接入的设计目标；配置和额度读回不代表测得业务请求并发峰值，也不覆盖其他运行实例。

主配置 `execution_enabled=true`，未配置 `local_cleanup_enabled`。部署 `五步接入-手动运行` 的默认参数仍为 `run_mode=check`。旧 README 和部署说明中的“真实执行关闭”属于旧说明，不能覆盖当前配置事实。确切观察时间和身份见 source-snapshot.json。
