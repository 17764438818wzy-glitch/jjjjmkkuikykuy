# 第四步到第五步交接约定

版本：`paperflow-nas-handoff/1`；日期：2026-10-29。

## 交接单位

每篇论文的一个已接收版本对应一份交接清单。沿用 H2.1 的论文编号、正文编号、附件编号、版本和路径，不重新识别附件、不重新生成画像。整篇的必要 RAG 内容全部核验后即可进入第五步，不等待同批其他论文。

MD 用于保留正文画像和每个附件的说明、目录；第四步到第五步的机器交接使用 JSON。这样第五步可以准确识别每个原件、校验哈希和恢复执行，避免从自然语言说明猜测删除范围。

## 第四步交付的内容

| 字段 | 内容与校验要求 |
|---|---|
| `schema`、`handoff_id` | 接口版本和整份清单的内容身份；修改内容后必须重新核验，不能只改 ready。 |
| `validation_scope` | `production` 或 `isolated_fixture`；合成 RAG 证据只能用于明确绑定隔离目录的演练。 |
| `paper` | 原 H2.1 inventory，原样保留。正文封包的原生 revision 与这里的 inventory revision 分别校验，不互相替代。 |
| `files` | 本篇需要 NAS 保存的全部正文原件、副本及附件原件。每项保留原 file_id、kind、path、relative、bytes、sha256，并增加文件对象指纹。 |
| `intake_receipt`、`inputs` | 原接收回执及正文封包、正文回执、附件回执等精确引用。 |
| `rag.body` | 原封包和原文档身份；各专业正文／图片库、文档、切片及检索核验证据。目标库必须与封包路由一致。 |
| `rag.attachments` | 每个附件的原件身份、主专业附件库、说明 MD 的各专业目标、切片和检索证据。主专业 MD 库必须与原件绑定的库一致。 |
| `evidence`、`retained_evidence` | 必须保留的封包、MD、接收／入库回执、显式提供的模型请求和响应等恢复材料，逐项绑定路径与哈希。 |
| `intermediates` | 具有完成、可再生、单篇独占证明的缓存清理候选。第五步还要复核范围、占用、引用、对象与内容。 |
| `retained_intermediates` | 因共享、身份不明、内容变化或属于恢复证据而保留的项目及原因。 |
| `status`、`reasons` | `ready` 或 `not_ready`，并列出缺项。 |

压缩附件按原件保存；说明 MD 提供简介、包内目录及原件引用。压缩包的成员不自动成为独立附件原件，也不因列出目录就声称 LLM 已读取成员内容。原件仅存入主专业对应的 RAG 附件库，其他专业的说明通过原件身份引用它；NAS 保存完整原件。

## 何时允许交给 NAS

第四步检查正文来源哈希、封包封印、原生任务身份、专业路由、文档身份、切片内容哈希和已有检索核验回执。附件必须逐个覆盖 H2.1 的附件集合，原件和当前 MD 均已核验；无附件时交付明确的空集合，不创建附件上传工作。

附件原生回执可能仍为 `paper_identity_only`。正文完整核验后，交接清单按同一 paper_id 和正文来源哈希建立到正文 targets 的明确关联，标为 `verified_paper_source_binding`，同时保留原生关联状态。这不要求重传已经成功的附件。

“上传接口已接收”或“附件已完成”都不足以产生整篇 ready。正文缺失、正文部分完成、目标库不匹配、切片或检索证据不足、缺附件、错篇、清单改变，均不进入 NAS。此交接校验读取已经落盘的核验结果，本身不发起上传或实时检索；本轮不能以合成结果声称真实整篇 RAG 已完成。

## 第五步接收与执行

第五步候选入口为 `Stage5Receiver`，复用原生 `archive_originals`、归档回执、逐文件清理日志与恢复机制。

1. `receive(handoff)`：复用第四步验证器。`not_ready` 返回零 NAS 操作、零删除；ready 时冻结交接证据，保存原证据到快照的映射和接收记录。
2. `archive(work)`：逐项复制正文和附件，NAS 读回校验大小与 SHA256，保存 manifest 和持久 NAS 回执。任何缺件或校验失败都不能开始本地清理。
3. `cleanup(work)`：再次校验已接收的身份、NAS 证据和清理范围；删除本篇清单内的本地原件及符合条件的缓存，逐文件保存 intent 和完成记录。
4. `resume(person_dir)`：从持久索引、冻结证据和日志恢复第五步。已删除文件通过原删除记录核对；不回到正文／附件准备，不重新调用模型，不重建 RAG 文档。

执行范围必须绑定配置中的本地资料根目录和记录目录。历史 source 映射用于追溯，不能扩大删除范围。第五步只派生含对象指纹的执行 inventory，保留原始 H2.1 清单和文件编号；同时支持原件位于学生根目录的 H2.1 布局。

## 清理与保留

| 对象 | NAS 与本地处理 |
|---|---|
| 正文原件、附件原件 | NAS 全部复制并核验且持久回执完整后，才按冻结清单清理本地。 |
| 解包临时文件、转换预览、临时图片、提取文本、工作副本 | 只有完成、可再生、单篇独占且无其他引用的明确候选才清理；它们不代替 NAS 中的原件。 |
| 最终正文画像 MD、附件说明 MD、模型请求／响应、原封包、接收／入库／NAS／清理回执、索引、日志 | 保留，用于追溯、读回和中断恢复。 |
| 生产归属证明 `producer_record` | 无论后缀是什么都属于必须保留的证据；不得同时进入清理清单。 |
| 共享、被占用、内容／对象变化、归属不明的文件 | 保留并记录原因；占用解除后只恢复第五步，不能通过重新跑模型解决。 |
| 个人目录及清单外资料 | 不递归删除，不因本篇完成而删除同目录其他内容。 |

“完成”要同时有 NAS 核验与清理日志闭合。明确区分 NAS 已核验、清理未完成和整篇第五步完成；保留项必须出现在记录中。逻辑文件删除不等于已测得物理磁盘空间回收。

## 本轮验收边界

第四步在隔离候选中完成 13 项测试；包含正文／图片错误库、附件主库不匹配、生产证明伪装、错篇、缺附件、证据变化、对象替换、无附件、共享缓存、证明文件交叉引用和本地原件已删除后的证据读取。

第五步接收同一实现和夹具，执行独立的真实 NAS 复制、读回、限定样本清理及中断恢复。正向演练的 RAG 回执是合成的；实际附件样本只有附件完成，整篇为 `not_ready`，必须保留正文和附件，不进行真实资料清理。最终结果另见联验报告。

本约定和接口均为候选交付；未据此改变正在运行任务、启用生产清理或调整真实并发配置。
