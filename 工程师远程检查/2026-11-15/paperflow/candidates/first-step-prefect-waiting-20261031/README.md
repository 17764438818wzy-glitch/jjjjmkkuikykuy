# 第一步与等待前处理：隔离候选

此目录是候选代码，尚未替换现有页面和服务。本次按要求未运行测试或启动候选。候选有独立状态库、交付和登记目录；不会读取现有任务库来重跑或删除旧任务。

候选使用同一台 Prefect 服务中的独立部署。一个页面任务绑定一张大工单，筛选和分类显示为其任务；通过分类、完成交付与登记、且接收身份核验通过的每个文件夹建立一张子工单。子工单留在独立的暂停工作池，不启动前处理。第一步完成后大工单在 Prefect 中挂起等待，释放执行槽位；页面显示“等待前处理”，任务的开始／暂停意图决定是否继续接收该任务的文件夹，挂起本身不等于用户点击暂停。页面只在接收记录和 Prefect 工单均可核验时显示等待数量；其他后续阶段未接入，数字保持不可用。

## 由用户启动候选

候选已对齐另一个会话的 Nimble 启动绑定、断线暂停和未知请求保护，并与正式第一步共用 Nimble 请求锁。由您在 PowerShell 中执行：

```powershell
& 'F:\论文预处理系统\预处理系统2\candidates\first-step-prefect-waiting-20261031\start-candidate.ps1'
```

脚本会在统一 Prefect 上登记本候选独立的部署和暂停工作池，并启动本机候选进程；它不会自动开始任何页面任务。打开 `http://127.0.0.1:18795/`，页面顶栏会标明“隔离候选”。如果端口已被占用，脚本会停止启动，不会接管已有进程。日志保存在本目录的 `sandbox\logs`。

建议使用之前未提交过模型请求的小型模拟资料文件夹，由您自己点击新建、选择文件夹、开始和暂停，再核对 Prefect 页面中的上下级关系和等待数字。候选与正式第一步共用 Nimble 及其请求锁，但候选不包含旧任务的模型请求日志，不能拿旧任务中结果未知的资料重复提交。一次只暂停或删除所选任务；其他任务应保持各自状态。暂停时已在提交中的文件夹工单可以完成入等待队列，但不会开始前处理。

使用完毕，先暂停候选任务，再执行：

```powershell
& 'F:\论文预处理系统\预处理系统2\candidates\first-step-prefect-waiting-20261031\stop-candidate.ps1'
```

停止脚本只处理启动记录中进程身份仍匹配的候选进程，保留候选数据及 Prefect 工单。候选工单和工作池不会自动迁移为正式服务。原始资料、旧任务及结果未知的模型请求不会由启动或停止脚本清理。

## 尚未验证的范围

按用户要求，这份代码、启动脚本、Prefect 父子显示、任务控制与大批量等待数字均未运行验证。候选用独立页面和独立状态库；正式页面不会因为修改候选而自动变化。大批量工单统计采用后台串行核对，核对期间显示 `—`，实际速度尚未验证。
