# Paper-title delivery naming implementation plan

**Goal:** Carry verified paper-title names to actual downstream inputs while preserving originals, cached model requests and sealed RAG/NAS identities.

**Architecture:** Build an immutable, per-paper, per-file named delivery copy, verified against the received source identity, and let new body and attachment work read it. Existing material, model requests, sealed packets, and remote receipts remain bound to their original paths and names; missing titles remain explicit and do not block body work. Do not invent a title or rename an existing remote object without a compatible recovery mapping.

**Tech stack:** Python, Windows paths, existing Prefect adapters and unittest fixtures.

## Global constraints

- Source originals, received inventory and identities remain unchanged.
- Body: `论文题目.原扩展名`; attachment: `论文题目_附件01.原扩展名`.
- Same-title papers and same-named attachments remain isolated by stable paper/file IDs.
- Completed or uncertain model histories are never replayed, repackaged, or rebound to a new path.
- Source and copy SHA256, size, and file-to-paper association must match before use.
- Missing title remains visibly unknown; processing can continue on the original.
- No hot deployment into a running Prefect flow. Remote mutations require their own verified identity-compatible path.

## Review focus

- Source mutation while copying: reject and preserve both previous evidence and original.
- A pre-existing delivery copy or manifest differs: fail closed rather than overwrite.
- Missing or unsafe title: no guessed name and no traversal.
- Same titles/filenames across different papers or versions: no collision or mixing.
- Existing material/request and raw attachment identities: reuse original binding without changing receipts.

## Tasks

1. Add failing tests for named body/attachment copies, byte/hash verification, missing names, collision and mutation protection; implement the smallest guarded copy helper.
2. Add failing tests showing fresh body preparation consumes the named copy, while existing material or requests stay on their original path; wire the helper into `Backend.prepare`.
3. Add failing tests for fresh attachment evidence consumption with the named copy while retaining the original item identity and completed request compatibility; wire through the existing evidence path.
4. Run the relevant receipt, body, attachment and recovery suites. Independently review the candidate and test with real source bytes only in an isolated directory, without a model call, upload, or mutation of the running flow.
5. Recheck runtime/manifest and decide the safe deployment boundary. Enumerate the five already-published papers with missing source titles; preserve their remote identities until titles and a recovery-compatible naming mapping exist.
