# 后处理服务器优化

目标：复用服务器上的固定运行文件，减少单个 Prefect 小工单的重复准备和重复处理；正文封包、附件说明、回执和等待 RAG 的接口保持不变。

范围与约束：

- 沿用现有正文和附件脚本、离线分词器、服务器容量和原始小工单身份；任务页的开始／暂停继续控制新工单。
- RAG 占位保持，历史完成和未知工单及其记录不改、不重跑；不增加流程锁或调度器。
- 固定的 Wine 系统文件与 Python 文件在服务器创建一次只读共享副本。每张工单仍有自己的前缀、可写状态及 F: 材料映射；共享文件在相同文件系统通过只读硬链接复用，不使用单个共享 Wine 前缀。
- 输入在现有入口校验；单次处理内复用结果，避免为了生成同一个回执再次运行正文和附件处理器。保留正文还原、封包清单、哈希、来源和回执交接。
- 仅为新的已暂停主线准备独立版本，保留旧版供原记录核对和回退；不改变当前任务状态、并发数量或 RAG 占位。
- 用户保留真实及合成测试权，本次不运行测试、不启动处理、不调用模型或 RAG；只做源码审阅、语法静态解析、版本及暂停状态读回。不能把加载或静态检查表述为实际提速或功能通过。

工作顺序：

1. 从实际运行版本建立独立候选，简化临时运行环境准备及同工单重复处理。
2. 检查新代码与共享文件使用方式，确认旧工单、清理、身份及结果接口不会改变。
3. 创建服务器端独立业务和服务版本，固定共享运行文件；在任务仍暂停且没有正在处理工单时接入主线。
4. 只读核对版本、并发、暂停、RAG 占位和历史工单；由用户决定何时点击开始测试。
