## 2026-10-31 的候选基线

这里的文件均未接入主线或 Prefect，也不会自动运行。`delivery_inventory.py` 仅读取接收回执、检查交付副本并构造清单；返回值明确写着不授权归档和释放。它不代表后处理、RAG、NAS 已完成。

`effect_journal.py`、`guarded_rag_client.py` 和 `native_ingest.py` 是尚未接入真实控制器的 RAG 发送边界候选。测试使用假任务准入、假读回验证和假远端。网络响应未知时保留发送意图及文档占用，不能直接重发；原生任务报告 DONE 后仍不释放占用，精确切片读回和持久回执后的安全释放尚未实现。同步写入也需要真实读回和持久回执验证器，测试注入的假验证不能用于生产。测试中的两个进程共用一个 SQLite 日志，但实际工作进程是否使用同一个不可丢失的日志、其他写入者是否受同一文档栅栏约束，均尚未确定。原生正文仍需绑定实际封包、逐条 token 资格、远端流水线和运行健康状态。

同步释放当前依靠 guard 调用顺序：内部 journal 释放方法本身不核验不可变的读回回执。正式集成前必须把回执及身份校验固定到释放事务，或建立等效的、不可绕过的调用边界；返回已保存但尚未释放时的崩溃对账也尚未实现。

`tests/test_nas_delivered_fixture.py` 使用合成文件和临时目录，复用原有归档写入与逐文件下载读回核心；并用合成接收回执验证交付副本可被归档。它不是生产 NAS 接口，也没有实际执行真实文件清理。

`cleanup_snapshot.py` 只读地记录交付副本的哈希、大小和 Windows 文件对象身份，不删除文件，也不授权释放。清理只能在新的后处理交付、正文和全部附件/专业的 RAG 完成证据、逐文件 NAS 持久证据、文件对象和共享引用、真实工单准入及释放授权都建立后，对冻结清单中明确允许的交付副本逐个执行。来源原件、垃圾、证据、回执和封包不应被清理。旧清理入口假设待删文件位于原资料库，不能原样用于新的交付副本；这部分新适配尚未完成。

快照验证回执声明的副本路径和内容，但还没有证明副本与来源原件不是同一底层文件对象；它也没有限制入参只能指向本地盘。正式释放前须另外核对文件对象、共享/硬链接及位置，不能把这个时间点快照直接当删除许可。

本机到 RAG 服务器 8088 和既有 NAS 主机 445 的 TCP 连接通过，RAG 首页 HTTP 返回 200，RAG API 只读鉴权返回成功。Windows 原有 NAS 凭据曾返回 1326；按用户指示，现已替换 NAS 主机名和 IP 对应的两条已保存凭据。普通 Windows 进程分别通过主机名及 IP 成功读取共享和现有目标目录的元数据、列出目录。基线当时尚未验证 NAS 写入、真实业务入库或删除；后续单份隔离自测见上方。既有目标目录不自动作为新流程的目标。
