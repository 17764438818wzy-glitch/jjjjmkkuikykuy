# 资料组交付包：接收侧适配候选

本目录是从现有接收侧代码制作的独立候选，未覆盖主目录，也不是已加载的 Prefect 部署。它不含正式配置、运行目录或虚拟环境，不能直接作为独立实例启动。上游交付代码本身未改动；候选中的 `group_delivery.py` 复用其交付清单和副本校验，并为接收侧增加逐项错误收集。

## 接口

- `receive_handoff(store=store, delivery_dir=目录)`：读取已发布的交付目录，登记能核验的正文和附件。原有 `receive_handoff(handoff, store, ...)` 仍可使用。
- 接收命令入口增加 `--delivery-dir`，旧 `--handoff` 仍保留。包内证据只从交付清单读取；调用者另传的证据列表不成为额外读取来源。
- 统一 Prefect 入口新增 `run_mode=receive`，支持单个 `delivery_dir` 或列表 `delivery_dirs`。此模式只登记接收，不进行分流或调用下游业务；不依赖模型/RAG并发额度。候选未同步到 Prefect，以上字段目前不是线上部署的接口。
- 包接收回执增加 `delivery_ref`，保存清单路径、哈希和交付编号；逐项保留原来源路径、实际副本路径、正式文件编号、来源绑定和必要的历史回执引用。

登记时按清单和原 handoff 校验组身份、快照和版本，逐文件核验大小、哈希和路径边界，包含垃圾和未确认文件。未形成可核验副本的项不回退读取原路径；证据问题和副本错误会保留为不完整原因，不抹掉其他已接收项。

附件证据须由清单声明、匹配原附件并具有完整连续版本链。包文件哈希不自动赋予文字或图片可信来源；已有来源绑定与独立证据规则继续生效。有问题的证据不会作为完整历史允许新的附件请求。

`read_receipt()` 重读时，若交付副本或证据后来受损，磁盘上的 `paperflow-receipt/1` 不变；返回的当前观察使用 `paperflow-receipt-observation/1`，其中 `receipt_id` 指向原回执，而不是观察对象自身的哈希。当前状态和逐项可用性以观察结果为准。

## 兼容范围和保留事项

- 同一登记身份的旧交付包可通过历史接收回执核验并复用已保存的工作记录，不改写旧请求、回答或命名证明。旧 JSON 和旧回执保留原入口。
- 早期旧 JSON 工作如果只记录上游原路径、没有可核验的历史交付副本，恢复会保守停止，不能因同哈希就改写历史请求或读取上游原件。已有完整缓存仍按原身份保留；此类未完成工作需要另行核对来源映射。
- 交付目录是不可变输入，不进入现有本地删除范围。现有第五步同时使用删除范围检查，因此包来源在该旧路径上会被挡住；本次不声称旧五步整链已适配或验收。
- 按用户要求，本次未运行测试、真实资料、模型或业务流程，也未重载、同步或修改正在运行的 Prefect。语法和只读代码审阅不等同于功能验收。
