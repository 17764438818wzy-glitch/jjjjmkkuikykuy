# 接收与前处理队列统计接口设计草案

## 目标和范围

为前端提供跨第一步任务的“等待前处理”数量。统计单位是资料组，而不是文件、模型请求或 Prefect 槽位。本窗口负责接收、核对、接收状态和等待数量接口，不实现正文解析，不修改前端，不运行真实论文处理。

**2026-10-30 用户调整范围：本次只做“等待前处理”接口；“前处理中”数字和接口待该阶段真正做好后另行整理。下文的前处理状态说明仅用于保留未来衔接边界，不是本次交付第二个统计接口的授权。**

用户已明确：直接使用上游现有交付副本，不再复制整套资料；一个总目录下保留各资料组子目录；垃圾文件不进入下一流程。现有文件的实际层级是 `classification_root/tasks/<task_id>/deliveries/<group_id>/<version>/`，可作为总根目录下按任务、资料组和版本组织的来源；不暗自将各组移动、平铺或重命名。上游原件、交付目录、登记回执及其身份保持不变。

## 已核实的现状

- 第一阶段逐组分类、交付和登记；任务接口提供组状态、论文编号、回执及交付目录。
- 本地 `read_registered_item` 只能核验并返回一组瞬时结果，尚无自动发现、持久接收记录或队列。
- 上游登记数量不是本地已接收数量。旧前处理路径没有可靠、完整的实际开始和失败事件；现有未接入的阶段候选的 running 也可能包括等待资源。
- 页面上的两个数字当前尚未接入真实数据。

## 方案与取舍

直接把上游登记数量当作等待数量，或把 Prefect 的任务运行状态当作前处理中，无法满足用户对已接收和实际开始的定义，予以排除。

拟复用现有回执与单组核验能力，增加本地持久接收状态，并从状态记录读取等待数量。状态记录属于本地接收域，不改写第一步的状态数据库。现有上游接口继续作为资料发现入口；旧的整篇五步流程和未接入的阶段候选不直接作为实时事实来源。实际前处理开始及结束的状态接线和第二个统计接口留待后续；在该接线完成前不能声称等待数已经排除了其他路径实际开始处理的组。

## 状态与数量

1. 仅当分类通过、交付完整、登记成功，且本地对身份、回执、正文及附件完成核对并持久记录接收后，该组进入 `waiting`。须检查本次实际观察状态和逐项问题，不能仅凭原始回执的 stored_state 或正文可用标记认定完整接收。
2. 前处理方在真正取得所需资源、即将开始前处理时，报告对应的资料组和回执版本；在一次原子操作中从 `waiting` 切换为 `processing`。领取任务或等待资源不算实际开始。开始和结束事件须绑定执行者、尝试编号或代次，重复事件可识别，旧尝试不能覆盖新的状态。
3. 前处理结束、明确失败或结果未知，应分别记录并退出对应实时状态；进程失联、状态缺失或竞争未确认时保留未知，不据此自动重跑或伪称正在处理。
4. 两个数字由同一份数据库快照按组计数，计数范围为全部第一步任务。以任务内资料组为接收来源单位；反复发现同一任务、组和回执不重复计数，同一来源组的新旧回执不能同时冒充两个待处理版本。跨任务相同论文、新回执或材料变化需保留来源和版本；若与已有处理中材料存在归属或复用冲突，隔离待核，不能仅凭相同 `paper_id` 或哈希合并或重复启动处理。
5. 垃圾不出现在交给前处理的正文、附件文件列表。未识别、未登记或未通过本地核验的组不进入 `waiting`；保留原因。
6. 上游全量发现未完成或局部扫描失败、必要回执与文件失效或身份冲突时，等待统计通过可用性字段和 `null` 明示，不能把未知显示为 0。已知失效条目保留原因并移出可处理的 `waiting`；重新核验不能取代持久删除联锁。按用户后续要求，本次等待数以本窗口接收记录为准，消费方未接线时仍可报告本候选中尚未移出的已接收数量；响应中的 `preprocessing_handoff_connected=false` 表示它不能证明其他入口尚未开始处理，待实际消费方接线后才能作为完整的前处理等待数。

## 消费端状态事件契约

实际消费端通过受控的内部接口或库调用报告状态，不能由前端点击或 Prefect 领取状态冒充实际开始。开始事件须携带 `task_id`、`group_id`、`receipt_id`、执行者身份、单次 `attempt_id` 和递增代次；仅当前有效 `waiting` 版本可原子转换，重复的同一次事件幂等，旧代次不能覆盖新代次。结束事件带相同尝试身份及结果状态和证据引用；失败、进程失联或结果未知分别保留，不自动重放。事件提交与实际函数调用之间仍有崩溃窗口，应由消费端对执行者和结果进行核对，无法确认时进入 unknown。具体传输与调用位置须由真正的前处理方接入；目前没有现成上报源。

## 拟议接口

以下路径和字段是待实现的接口草案，尚不是可调用的生产接口：

`GET /api/v1/local-intake/preprocessing/summary`

```json
{
  "scope": "all_tasks",
  "waiting_count": null,
  "waiting_available": false,
  "as_of": "2026-10-30T00:00:00Z",
  "upstream_scan_completed_at": null
}
```

可用时等待数量为非负整数；不可用时为 `null`。本地快照时间和最近完整上游扫描完成时间分别表示，不能用其中一个代替另一个来源的新鲜度。示例只说明结构，并非实际统计。本次不提供 `processing_count`。接口地址和端口在候选服务集成时确定，再交给前端。

## 接线和保护边界

- 新资料按组发现，不等待整个 500 组批次；对动态变化的分页结果反复核对，不能把单次翻页当成可靠游标。跨多页扫描失败时不能声称全量准确；两次扫描之间被删除的任务可能无法发现，反复扫描本身不能保证绝不漏组。
- 上游已有的任务详情 GET 会触发任务状态刷新，不应宣称该查询绝对没有副作用。正式启用自动发现前应核对影响。
- 不复制交付副本时，上游删除任务可能移除这些文件及回执，且可能发生在入队前、等待期间或读取期间。现有删除功能尚未识别本地占用。自动删除联锁尚未实现；正式启用前需要明确协调方式，且不能把一次接收核验或随后重验当作永久可用保证。
- 本窗口可以定义并实现状态接入协议，但前处理真实开始、结束事件必须由实际消费端接线。状态写入和实际调用不可能跨进程绝对原子，崩溃时需要核对执行者并保留未知。未接线前，不能宣称“前处理中”是实时数字。
- 不改上游分类及登记规则，不凭接口或示例数据声称服务已部署或任务已接入。

## 验证计划

用合成资料和隔离临时状态库验证接收成功、未登记、回执身份不匹配、原回执已接收但当前观察有损坏、重复发现、等待到处理中原子切换、重复或迟到事件、完成和失败退出、执行者失联、原文件删除、扫描不完整及接口不可用等情况；验证垃圾不在下游输入清单。检查跨任务和新回执时不会混用或冒充已验证去重。不调用真实模型，不启动真实论文任务。真实自动接收和实时处理状态必须在实际接线后单独核验。
