这里是隔离候选，不是已安装版本。没有启动真实后处理或 RAG 上传；两道运行门禁的状态由实际控制库决定，不能仅由本文件推断。

## 此次展示修复

`waiting_api.py` 把后处理的本地、Prefect 见证复核移到后台；未筛选的阶段与结果可共用一次完整核验。并发页面请求短暂共享同一个来源快照，各用独立副本和相同序号；共享读取超过 200 毫秒，跟随请求会独立读取原有摘要，但其后处理部分显示未知，不能重绑缓存。更早的请求不得覆盖较新的来源。异常或不可核验时显示“—”。

该展示缓存有明确时效：本地复核最多使用距复核**开始** 8 秒内的观察，Prefect 复核最多使用距观察**开始** 15 秒内的观察，完整文件哈希最多使用距全轮核验**开始** 45 秒内的结果。开始计时并不等于完成时仍新鲜；`as_of` 是完整核验原有时间，不由后台见证刷新。状态发生变化可能先看到旧数，后台发现变化后清除缓存；执行准入另行核验，不能使用展示缓存替代。

真实 HTTP 的其他上游摘要仍可能慢；这里只移除了后处理见证在请求中的同步等待，没有证明接口始终不超时。经过 5 轮模拟，三个列表并发时可共享快速快照；快照超过等待窗口时结果仍可能为未知，尚未在真实负载下验证。

每次检测到接收扫描完成时间变化都保守作废旧见证；扫描中或失败显示未知。接收器扫描结束后等待约 30 秒的现状下，如果完整核验要 35 秒，就可能持续无法得到可用值。`upstream_scan_completed_at` 是墙钟时间，可能回拨或重复，只是来源变化提示，并不是严格单调版本，不能据此声称完全消除来源 ABA。当前不跨扫描复用旧完整哈希结果。

隔离测试：`api_fix_next/tests` 和 `projection_fix_next/tests` 共 93 项通过，合成数据覆盖慢见证、时效、来源交错和多列表并发；没有执行真实论文、模型请求或上传，也没有证明长时间真实并发。

## 服务器迁移所需核对

`migration-source-hashes.json` 列出本次只读盘点的 145 个候选、页面、运行包及配置文件的 SHA256；配置只记录文件哈希，不记录配置内容或凭据。这是按目前代码依赖整理的核验清单，不声称已完整覆盖服务器所需的系统依赖、部署配置或模型资产。

- 后处理业务脚本包括 `runtime_next/{stage_runtime,live_runtime,batch_next,run_batch}.py`、`folder_state.py`、`results_next/postprocessing_results.py`、`generation_mainline_bridge.py`、`body_adapter.py`、`generation_attachment_adapter.py`、`generation_attachment_card.py`、`folder_processor.py`、`handoff_inputs.py`、`prefect_slot.py`、`stage_gates.py`，以及调用它们的 `paperflow_prefect` 包和离线业务脚本。清单还保留常规附件适配器，实际运行入口以依赖和后续迁移核验为准。
- `legacy.bind()` 根据 `source-manifest.json` 核验旧业务脚本。当前所指清单含 581 个 Python 文件，本轮只读核对 581 个均匹配原清单哈希。清单保存本机绝对路径，迁移时必须在服务器重新核对路径与内容身份，不能照搬原路径，也不能把旧控制器一起启动。
- 运行配置涉及 `prefect-paperflow/config.json`、`runtime-config.json`、`catalog.json`、前处理/接收配置、原模板与专业目录，以及独立离线计数器的运行库、词表、模型文件、缓存目录和运行时清单。当前本机使用的离线计数器通过 WSL 辅助运行，服务器的系统类型和对应文件需要另行核实，不能把 Windows 虚拟环境直接当成服务器环境。
- 需要能一致核验已登记交付副本、前处理材料、原始回答、请求记录、来源图片、回执和输出文件；保存的路径、哈希及文件夹工单身份都必须正确映射。控制库、接收库、暂停/删除门禁和共享锁的跨主机一致性需要单独设计验证，不能假定把 SQLite 和锁目录放到任意网络共享就具备原事务语义。
- 当前投影的 `process_alive()` 用 `psutil` 检查投影程序**所在机器**的 PID 和启动时间；阶段表没有记录主机身份。本机投影不能据此确认服务器上的进程活性，应改为服务器本机的可信观察并验证主机身份，或显示未知。相同的跨主机身份问题还需要在执行与恢复路径中逐项核对。
- Python 依赖及系统工具应按 `requirements.txt` 和业务实际导入核验，至少涉及 Prefect、FastAPI/Uvicorn、psutil、filelock、Pillow 和离线计数资源。保留 Prefect 的文件夹级并发目标 8；配置数值不是服务器持续 8 并发已测试的证明。

迁移、联机以及 RAG 上传门禁由主任务统一处理；本盘点没有复制配置、更新远端服务、放行队列或发起真实处理。
