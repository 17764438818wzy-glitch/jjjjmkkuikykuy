# 后处理统计只读投影候选

`projections.py` 是现有前处理保留交接、LLM 完成登记、新文件夹 Prefect 工单、后处理阶段/结果/回执的被动读取适配。`waiting_cli.py` 是最小注入候选，不扫描、不派单、不创建表、不调用 LLM、不上传 RAG。缺少来源或不能一致核验时返回未知。

每次完整核验读取控制库和本地队列业务快照，核对来源、注册回执和保留副本、前处理材料、文件夹及阶段 Prefect 身份、持久回执及其产物哈希；Prefect 状态和业务快照在结束前复核。控制库任何并发提交或数据库文件身份改变会使结果未知。队列仅忽略接收心跳、扫描时间和保留复核的 `updated_at` 时间戳，仍比较保留身份、状态、错误及会话等业务字段；所有业务表快照按事务读取并首尾比较。不同数据库和 Prefect 没有跨服务原子事务，因而这是基于前后证据的观察，而不是对所有未来状态的保证。

`source_llm_generation` 必须等于上游 LLM 行代次且满足 `1 <= source_llm_generation <= job.generation`；实际执行仍核验大工单当前代次。阶段 `reserved`、提交不明、暂停前拦截、取消栅栏和身份/交付不明均不重复算等待、不算通过，显示待核对及处理中未知；只有验明真实 TaskRun 且 PID 与进程创建时间匹配的执行才算处理中。等待 RAG 只计持久通过回执 `waiting_rag`，`receipt_held` 独立提示。

通过结果用 `FolderStageStore._inspect_receipt` 核对已接收回执和所列产物哈希；此投影不再次执行正文封包的完整语义、隐私证明或重新处理。结果标题复用已有 `_add_result_titles`。缺少真实未识别覆盖依据时，未识别总数为未知。

为支持较长的有限缓存，投影携带内部见证；每次返回前对比本地业务快照、复用旧 `_delivery_fingerprint` 检查交付材料、回执及产物文件属性、核查 PID；后台重复检查 Prefect 状态和身份。文件属性检查不等于重算文件 SHA256，完整核验按 API 的有限时限重做；参见 `../api_next/README.md`。当缓存见证不存在时不会采用较长缓存。

2026-11-01 只读实测，268 组全量阶段和结果投影均可用，阶段显示 268/0/0，结果为 0/0/未知。单次完整核验约 13–16 秒，轻量本地检查约 0.74–0.76 秒，远端后台复核约 1.24–1.45 秒。进程内 API 联测在合成的工单摘要外壳下持续跨过 8 秒缓存期，最大接口耗时约 2.13 秒。上述数字仅是当时快照和试验，不代表线上已安装或实际后处理完成。

`read_only_probe.py` 用 SQLite `mode=ro`，不初始化队列表、不启动监听服务、不派单，输出仅含可用性、聚合数量、耗时和安全错误类型。源代次候选已合入 `runtime_next` 后应再次运行投影、API 和控制组合回归；真实库的字段迁移须由主任务单独控制。
