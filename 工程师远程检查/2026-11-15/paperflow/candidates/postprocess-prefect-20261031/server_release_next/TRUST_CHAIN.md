# 历史版本只读查询的信任缺口

本文件记录切换前仍未完成的工作，不安装服务、不修改 gate，也不放行任何工单。

服务器窗口提供的 `postprocess-server-20261101/server-native-integrity-audit-60c7d357f49c4b8c9b12e5580853394e.json` 是一次只读快照：六个历史版本清单内已列出的 app Python 文件及 native 清单哈希当时匹配；该清单明确标注为 `pinned-known-files`，没有证明依赖闭包。Python 可执行文件有路径和哈希，但历史 app 属运行账户所有，该账户可以修改文件；标准库内容没有完整的逐文件固定证据。

另一次 `postprocess-server-20261101/server-pyc-audit-aa449f9694e04aecb37d25cc7b76a6ab.json` 检查了当时存在的五份 `remote_jobs` 字节码：其 code object 与对应当前源码的编译结果一致。这是快照结论，不能证明历史执行时相同，或证明未来文件不会变化。不得为页面验证清理、覆盖历史文件或字节码。

当前受限 gate 只按命令字符串放行；原 `inspect` 在 Python 模块已经加载后才有后续 native 清单检查，不能证明启动和导入时运行的就是当时清单中的字节。客户端注册表的 `rpc_script_sha256` 没有在该旧命令执行时直接验证。候选的未读脚本校验器也不能替代被导入的历史模块、标准库和解释器的信任。

项目中 `release_guard.py` 的 `ReleaseGuard.read_verified` 和 `PinnedFinder` 可复用其“读取后验证并执行同一份 Python 源码字节”的机制；但当前 finder 只管指定根目录的 `.py`，对其他路径返回默认导入，不能证明完整导入来源、既有 `sys.modules`、原生扩展、标准库及解释器。不能直接把它作为全部依赖已固定的证明。

服务器窗口已确认现阶段的外部信任前提为服务器运行账号、系统解释器及其 venv/site、操作系统、标准库和系统动态依赖；它们并未全部固定。`-I -B` 保留原 venv prefix，现场无业务对照时未预加载六版 app 模块，但 site/`.pth` 启动仍先于候选入口。静态审计未发现六版直接命名 app 依赖调用链中列举的直接动态加载方式，不能证明运行时依赖闭包。

候选 `server_verified_entry.py` 复用上述源码校验机制，并限定常规 app 导入来源；它不是沙箱。页面候选通过 `GuardedAppDelegate` 指向该入口，缺少固定 bundle 则关闭投影；据服务器窗口报告，入口与清单安装在独立目录，受限查询命令已放行，五个可访问版本的 native 无业务检查通过，尚未接入现场页面。2026-11-01 本窗口三张指定回执最初均未知；修复本机编码后再次观察，一张回执及特定未读检查通过，两张被该规则标记待核对，见 `ALIGNMENT-20261101.md`。精确命令见 `readonly-guarded-gate-proposal-candidate-20261101-v4.md`。旧稿和旧 bundle 已被替代。本机候选 `verified_ssh_transport.py` 保留原有有界 SSH 逻辑，子进程执行本机固定清单中的已核验 client/helper 字节，不再重新从磁盘打开它们；本机解释器及第三方依赖仍属于外部信任。

后续受控验证需要先形成并独立审核这些具体证据：

1. 每个可访问历史版本的服务配置、RPC、导入模块及其依赖清单，区分源码、字节码、原生扩展、标准库和解释器；注明清单不能覆盖的部分和由谁保证。不可用的 53ff 版本保持未知。
2. 由受控服务器 gate 固定只读引导入口并精确限制操作、路径和配置；不得只开放任意 `python -c`。候选对于常规 app import 执行已校验的同一份源码，拒绝未列入或来源不符的 app 导入，且检测预加载 app 模块。OS、解释器、venv/site 和未审核原生依赖依照上述约定作为外部信任，不能称作已被本入口逐项核验。
3. 在隔离环境复现文件替换、相同时间戳旧字节码、错误配置、路径/符号链接替换、外来导入和中途超时；这些情况应失败并保持未知。还需核对特定未读规则标记的两张工单，并验证不同负载下的观察时延。
4. 再核对正常单、未读缺陷单及执行未知单各自显示。页面或 Prefect 的现场切换仍按用户指令执行。

实时业务正确性、全部脱敏、RAG 接收和 8 并发稳定性均不由这一文件证明。
