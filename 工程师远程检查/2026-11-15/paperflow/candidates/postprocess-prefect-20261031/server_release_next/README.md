# 服务器后处理页面隔离候选

此目录只准备页面、只读投影和启动入口；不是现网发布目录，也尚未接入现网 8795 或 14206。它不启动后处理、不扫描或认领小工单、不发送模型请求，也不上传 RAG。执行资源仍由后处理窗口的 Prefect/服务器配置决定；本页面最多同时进行两个逐单观察，不代表后处理并发为 2。用户要求的后处理并发 8 需由服务器配置和真实调度另行核验。

2026-11-01 对齐及三张指定工单的回执观察结果见 `ALIGNMENT-20261101.md`。首次三张均未知；修复本机中文输入编码后，再次观察为一张通过回执与特定未读检查、两张该规则标记待核对。不得将这次观察理解成 RAG 上传成功。此后的共享后端变化和正式发布清单仍需另行核对。

现有 14205 继续提供前处理和 LLM；候选计划另用本机 14206 提供服务器后处理观察。两个请求独立，14206 失效时前处理和 LLM 不因它而变成不可用。候选队列观察以 SQLite 只读模式打开现有库，不调用旧队列的建表/迁移初始化，也不探测文件夹工作锁；它不提供前处理活动数。

## 展示口径

- 一张原始文件夹小工单作为一项；大工单用于归属，不按正文、附件数另加计数。
- 启用 `--partial-observation` 后，程序从登记账本自动发现已登记通过的工单，逐单核对原始 intent、来源、Prefect 和服务器回执；可以显示已核验子集的“至少”数量，不把它当成全局完成数量，也不显示全局等待 RAG 的数字。结果有观察时间，不表示 RAG 已接收，也不证明完全脱敏。
- “未通过”“未识别”当前不能得到可靠的服务器核验数量时显示 `—`；已登记但证据未核验的行写“已登记 · 待核验”，可与其他已核验行同屏，不计入已核验数量。
- 没有有效回执、结果不明、来源不可用或服务器不可核验的工单不得算入等待 RAG。运行中数量没有经核验的服务器活动证据时显示 `—`，不使用本机 PID 推断服务器活动。
- 原始回答与完整诊断在私有位置；页面只读，不把它们加入公开封包。

页面请求保护只保留短时观察快照，服务器回执使用内外层中更早的截止时间。控制数据库发生写入后，下一次 14206 请求会使内外层旧缓存失效；浏览器在有效期结束或从后台恢复时清空旧结果。检测与展示之间仍有时间窗口，浏览器正常前台轮询间隔为 5 秒，挂起或网络不可用时不能保证及时更新。未完成的读取显示待核验，不能把该缓存策略当作实时一致性或实际吞吐量保证。

逐单缓存目前仍依赖整本控制账本的版本；另一张工单状态变化也可能使已核验单重新观察。结果在有效期内会提前启动只读复核，但一次观察超过有效期时仍会出现空窗。真实多版本和 8 并发业务下能否稳定显示尚未验证。

当前 CLI 候选复用各历史版本现有 `inspect`，按固定清单逐个尝试；只有原回执、完整产物映射和身份通过现有核验，再检查未读限制。六版本注册表来自服务器窗口一次只读记录；其中一个版本的访问引用不可用，无法确认的结果保持未知。每个只读 inspect 最长 10 秒且共享总时限，慢查询或靠后的正确版本可能保持未知；修复编码后的三张指定样本耗时分别为 4.564、5.813、6.323 秒，不代表全量负载或其他样本时延。访问引用需要核验配置和密钥文件哈希，不复制私钥内容。

服务器窗口确认，现有受限 gate 只匹配固定命令和路径，原 inspect 在加载 app 后才核验部分文件。页面候选已要求经过独立源码固定入口：按六版固定清单读取并校验 app 源码，以同一份字节执行常规 import，未读脚本也逐次校验；缺少 guard bundle 时关闭服务器投影。据服务器窗口报告，候选入口及受限查询命令已安装在独立目录，五个可访问版本的 native 无业务检查通过；尚未接入现场页面。精确命令见 `readonly-guarded-gate-proposal-candidate-20261101-v4.md`。该稿采用 LF 行尾，脚本和 argv 与 v3 相同；v2 及更早脚本与 bundle 已被替代。旧版本查询脚本保留为实验材料，当前 CLI 不使用它。

该候选沿用服务器既有信任边界：系统解释器、venv 和 site 启动（包括 `.pth`）、操作系统与账号、标准库和系统动态依赖由环境保证，未全部逐字节固定。入口不作为 Python 沙箱；已批准代码通过直接 loader 或 `exec` 等方式可绕开普通 import 拦截。服务器窗口对六版直接命名的 app 依赖做过静态审计，未发现列举的直接动态加载，但它不能证明运行时完整依赖闭包。据服务器窗口报告，五个可访问版本的新引导 native 无业务检查通过；真实验证仅限上述三张回执和特定未读规则。

本机 SSH 子进程候选复用原有单次有界传输的校验和等待逻辑，但改为让子进程执行本机清单所核验的 client/helper 字节，避免校验后从磁盘重新打开及读取旧 app pyc；本机 Python、site 和第三方包依然是外部信任。传输的总字节上限包含新增的源码封装，大请求可能因此保守失败。

未读候选检查只针对私有校验报告中的 `normalized_unlocated_reading_declaration` 和 `unread_refs`：若出现该项而公开画像缺少固定提示，结果待核对；证据不全则未知。它不证明其他类型的未读/未提供材料都已核验，也不证明完全脱敏。它检查每个报告的固定路径，并与冻结计划的段数和编号交叉核对。实际 `verify_job` 还会读取冻结输入做完整性核验，不是只读取三种结果文件；单个关联 JSON 超过 4 MiB 会保守失败。

本机新增的是进程内部的缓存互斥与 SQLite `mode=ro` 版本观察，没有新增小工单或全局调度锁。服务器现有 inspect 通过 `mode=rw` 打开 ledger，观察路径只读业务数据，但数据库仍有正常读取锁；新版本查询候选使用 `mode=ro`。进程关闭时会停止接受新观察，已在执行的阻塞读取可能晚于关闭请求结束，需核实进程实际退出。

## 启动信任与切换前准备

1. 首先审查固定入口、历史 app 清单和精确 gate 命令，核对按版本认证、服务器配置与 ledger 实际对象一致性及现场解释器/venv 信任。检查新增引导与历史 native 映射是否兼容。随后才可通过各版本真实回执端到端验证；现有合成测试不能证明混合版本现场可用。
2. 对当前 8795 页面重新三方合并，保留人工重试等其他窗口的改动。该目录 `site` 是此前读取现网页面的候选副本，之后现网有变化就必须重新合并。静态资源应使用受控、不可随意修改的版本化发布目录；独立 `http.server` 本身不提供逐次校验，浏览器缓存也要重新核验。
3. 审核运行身份、Prefect 地址、原始任务和文件夹绑定、控制库与 intent journal 身份、服务器和 ledger ID、门禁和 service config。页面进程与执行进程是不同进程时，不能只凭 Python 对象相同来证明它们指向相同运行版本；需要核验这些实际固定身份。
4. 源码稳定后，用 `prepare_manifest.py` 生成后端依赖清单；静态站点用 `tests/prepare_site_inventory.py` 单独生成清单。独立复核清单和启动器、`waiting_cli.py`、`release_guard.py`、`release_layout.py` 的哈希。站点内容变化不直接使后端投影失效，站点发布仍须单独核验。草稿不是发布许可；第三方 Python 包目前核对版本号，不是完整包文件的完整性证明。
5. 受控的 Windows 计划任务动作应在执行本目录 `run_waiting_service.py` **之前**用独立固定值验证该启动器 SHA256；启动器用 `--cli-sha256` 校验并执行同目录 `waiting_cli.py` 的字节；CLI 以 `--guard-sha256`、`--layout-sha256` 在执行对应引导文件前校验其字节，再核验清单。计划任务动作/账户权限和这些独立哈希是信任根，不能从待校验文件自取期望值。
6. 逐单模式须显式传入 `--partial-observation`；历史路由须同时传入 `--history-registry`、`--history-registry-sha256`、`--history-access`、`--history-access-sha256`、`--history-unread-script`、`--history-unread-script-sha256`、`--guard-bundle` 和 `--guard-bundle-sha256`。部分参数缺失时不能静默使用历史路由。现网 14205 和接收扫描器不切换为该入口。
7. 准备切换时，确认其他窗口操作、14206 端口、进程及任务配置，制定停启顺序和验证方法。候选不会初始化队列库，但启动器会写指定的服务日志；不得回滚或覆盖现有数据库、journal、回执、原件、封包和门禁。

## 失效与回退

只读投影发生问题时，候选支持显式 `--closed-projection` 模式：在清单和引导仍可验证时，14206 的后处理及等待 RAG 返回未知，不连接远程后处理投影。若清单或启动信任不可核验，14206 返回 503；14205 由现有服务独立提供。不能无条件恢复旧本机后处理投影，否则可能把服务器任务误显示为本机结果。

任何切换或回退都应检查 8795 浏览器拿到的实际脚本、14205 和 14206 各自状态、各类数字与证据时间，以及小工单和大工单身份；未知项不得自动重试或重新认领。本文只是候选切换步骤，不表示已完成切换、全局真实页面已核验或获得 RAG 接收。
