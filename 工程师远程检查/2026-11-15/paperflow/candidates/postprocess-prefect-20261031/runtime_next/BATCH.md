# 后处理有界分批候选

`batch_next.py` 是候选库，不会自动启动。`run_batch.py` 只在显式指定大工单和上限时执行，不会打开门禁、发送模型请求或上传 RAG。执行前仍需独立核对门禁、数据源及 worker 代码版本。

`snapshot_waiting(database, task_id, max_folders)` 在只读事务中冻结一个大工单最多 `max_folders` 个候选文件夹，排除删除、暂停、已有阶段/结果记录和存在未完成或未知 LLM 请求的项目。它只筛数据库，不替代每一单预约时的完整接收回执、材料、模型原回答和 Prefect 工单身份校验。

`run_batch` 每次从该固定列表取最多 8 项，构造一个只订阅这批唯一 `task_key` 的 Prefect TaskWorker。它仍使用既有 `Coordinator` 的双门禁和 Prefect 全局 8 名额；一批中的某单失败、提交或结果未知、TaskRun 结束但状态未确认、worker 出错时，停止预约后续单和后续批，已经提交的任务保留并等待收尾。已预约或未知结果不自动重复提交。

提交请求可能在 worker 实际启动后才丢失响应；代码把该单加入在途观察后再发起提交，异常时继续等待已执行工作收尾。数据库阶段结果和 Prefect TaskRun 有不一致时保留记录供核对，不能自行重发。批次进入预约和提交事务时，候选门禁还会重新检查同批前面任务已观察到的失败或未知状态。

合成测试覆盖分批边界、排除未知和已预约项目、出错即停、提交响应丢失，以及使用临时本地 Prefect 服务时只领取指定 key 的任务。尚未用真实任务测试持续并发 8 或长时间运行。

暂停恢复后，快照允许先前有效的 LLM 代次不大于当前大工单代次；实际预约仍冻结并再次核对 `source_llm_generation` 和原回答证据。
