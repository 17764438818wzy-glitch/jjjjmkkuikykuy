# 人工重试状态提示候选

`RetryNoteObserver` 包装既有 LLM 结果观察器，沿用它原来的列表、分页、计数和前端 `order_note` 字段；只在逐单核验成功且还没有后处理预约、领取或结果时增加状态说明，并保留原有提示。原工单的失败历史仍由 Prefect 保留；它不改写历史，也不把 LLM 原始回答完成当成后处理通过。

现网 14205 入口使用同一次构建的 `live_runtime.build_runtime()` 的 `coordinator.verify_upstream` 及其控制库，包装既有 `ticket_observer` 后传给 LLM 页面服务，页面关闭时调用包装器的 `close()`。入口核对来源代码、控制库、Prefect 地址与等待池库身份；装配失败时继续使用原观察器。原前端已经渲染 `order_note`，不需要增加模型调用。若来源不可核验、已经产生后处理预约或数据在核验中发生变化，保持原有提示，不显示“等待后处理”；暂停或切换中的大任务使用不同提示。装配成功不等于真实重试流程已通过验证。

来源核验在后台执行，最多两个守护式只读观察线程、100 条正在进行、排队或已完成的核验记录；页面先返回原结果，避免逐单等待导致前端超时。已完成的提示最多保留 15 秒，返回前后通过控制库只读连接的 `data_version` 检查本机变更；最多 100 条的大页轮流核验，不因其他浏览器查看不同页而取消已有观察。旧页的慢核验可能延迟新页提示，但不会挡住原列表；如 100 条额度都被未完成核验占满，新记录会等待额度释放。后台观察线程采用守护模式，关闭页面时不等待正在执行的耗时读操作，但不能强行中断它们。包装器内部有一把短时内存锁，保护线程共享的缓存、队列和只读连接；它不是文件锁，不占用或调节 Prefect 后处理的 8 个名额，也不控制模型或 RAG。`data_version` 只观察控制库，Prefect、接收队列库和回答文件的独立变化未必立即使缓存失效，因此提示明确使用“核验时”，过期后需重新核验。

状态是一次只读核验的时点信息，Prefect 和本机控制库不是同一个事务。此候选不会证明后续 RAG 已领取、上传或可检索。测试只使用临时控制库、合成回答登记与替身来源回调。
