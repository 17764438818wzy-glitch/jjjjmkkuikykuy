# 服务器回执页面适配计划（隔离候选）

目标：继续使用原 Prefect 文件夹小工单的身份和已登记结果；只有可信服务器对原回执、完整产物映射及来源执行核验后，等待 RAG 才显示对应数量。无服务器活性证据时，后处理中为未知。候选不接入真实队列。

复用现有 `ledger_projection_next.snapshot` 的文件夹身份、结果和分页；复用 `RemoteReceiptInspector.inspect_many` 的批量回执检查及已有 `ledger_ui_next` 页面/API。新加一个服务器观察适配层，不替换被另一窗口修改的代码，不伪造本机产物路径，也不新增全局材料锁。两种口径分别标明登记信息和服务器观察，服务器观察只表示某时核验，不表示 RAG 已接收或持续可交付。

1. 在临时控制库和合成远端检查替身上先写失败测试，覆盖一文件夹多组件、服务器不可达、来源不匹配、文件映射不完整、证据过期、分页/台账变化和旧 PID 不能证明远端活性。
2. 实现 `server_projection.snapshot(...)`：读取一致的登记快照，在事务外调用由正式接线提供的权威来源核验与现有服务器批量验收；核验前后重查台账，绑定服务器观察和分页修订号。未能核验的计数保持未知；失败/未识别诊断在缺少可信远端证明时仍为未知。
3. 复制现有候选 API 与页面文件作为独立候选，使等待 RAG 使用服务器观察、过期即未知；复用三类结果展开和分页。不得修改现有线上文件。
4. 跑新旧相关合成测试并做独立复核；记录实际测试与未完成的真实服务器、Prefect 和上游权威来源接线。

现已增加 `scope_verifier.py` 与 `page_assembly.py`：候选装配复用原运行时、原小工单和冻结来源核验以及固定服务器回执检查器，空队列复用对方窗口的认证 probe。人工重试契约未闭合时、证据缺失或观察期间部署/来源改变时保持未知。正式接入仍须提供经核验的生产实例和有界配置；服务器活性还需独立可信证据。本候选不提供生产凭据或替代执行前的上游检查。核验过程中发生变化后又恢复到相同字节的情形不能由台账摘要排除。
