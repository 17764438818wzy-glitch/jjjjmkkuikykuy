# 服务器回执页面适配（隔离候选）

此目录没有上线到 14205、8795 或服务器。不会自动扫描、启动后处理、改变门禁、请求模型或上传 RAG。它是对既有登记投影和页面的覆盖式候选；`index.html` 引用的其他脚本、样式、vendor 文件仍来自现有页面服务，本目录不是独立完整站点。

## 观察与页面口径

- 复用 `ledger_projection_next.snapshot` 的原大工单、文件夹小工单身份和分页，再调用既有 `RemoteReceiptInspector.inspect_many`。同一文件夹的多正文分段、多附件只计一单。原回执和服务器检查生成的 Linux 路径、大小、哈希映射保留各自身份，不制造本机文件或把服务器路径伪装成本机路径。
- 本候选还要求映射完整覆盖原回执中正文包的全部引用，并至少包含 `article.redacted.md`、`profile.json`、`tree.json`、`assets.json`、`chunks.json`、`split-plan.json`、`source-map.json`、`manifest.json` 和 `READY.json`；正文和所需公开项的映射需存在。其他图片和文件按回执完整覆盖。真正的清单、原件、业务版本和文件哈希核验依赖已认证的服务器验收实现，不能以这个展示适配器代替它。
- `server_observation.basis=paperflow-server-receipt-observation/1` 是某时对来源、原回执和映射的观察；`current_delivery_verified` 仍为 `false`，不表示持续可交付、RAG 已接受、无识别缺口或完全脱敏。实际上传前必须独立复核。来源或服务器无法核验、回执不完整、观察过期、数据库前后变化时，等待 RAG 和等待后处理数量为未知。存在提交/执行但活性不明的小工单时，相关排队数量也为未知。
- 没有可信服务器进程活性证据时，“后处理中”显示 `—`，不会读取本机 PID 推断服务器活性。已通过数量要求服务器回执观察；未通过和未识别缺可信远端诊断证明，数量目前为 `—`，其登记列表可以展开并标注“证据待核验”。这两项的准确计数尚未完成。
- 等待后处理是原文件夹的**已登记等待数**，可包含处于暂停中的大工单；它不是可立即启动的数量。执行仍须检查任务暂停/删除、代次和门禁。人工重试相关小工单在后处理原工单契约解决前保持未知，不能以 LLM 回答完整证明已接通。
- 每次观察在服务器核验前后复查来源和台账，并把台账与服务器映射的摘要绑定分页修订号。观察从开始计时，最多 30 秒；API 缓存对过期观察降级为未知，并跨筛选页淘汰较旧不同结果。它不能排除观察之间变化后恢复的 ABA 情形，也不能证明观察结束后材料永不变化。
- 未核验的页面故障只返回固定阶段名称，例如 `source_recheck_unavailable`；不返回异常全文、论文内容、凭据或文件路径。列表和标题继续以文本方式渲染。

## 正式入口必须提供

`page_assembly.build_page(original_runtime=..., remote_runtime=..., queue=..., observer=...)` 是未启动的候选装配入口，返回 FastAPI app 和 `registered_projection`。它复用同一套原始运行时闭包、原控制库、原远端意图日志、同一个 task gate、现有 Prefect 来源观察、冻结材料核验、服务器检查器和传输器，不创建任务或扫描队列。运行时、接收队列和观察器仍须由将来正式入口提供并逐一核验；本候选尚未安装。

底层 `server_projection.snapshot(database, *, ledger_snapshot, component_id_fn, inspector, stage_store, verify_scope, probe_server=None, ...)` 不自行创建网络连接，观察前后会复用 `journal._ready(stage_store)` 检查同一意图日志及 task gate，即使没有回执也不跳过。`page_assembly` 还使用服务器候选已有的文件身份检查防止装配期替换控制库或意图日志。正式调用者必须同时提供：

1. 经证明唯一权威的控制库、现有 `ledger_projection_next.snapshot`、现有 `folder_completion.component_id`；所有任务、文件夹、冻结来源和已登记附件保持原身份。
2. 来自相同模块实例的真实 `RemoteReceiptInspector`，连接经过服务器身份固定、认证和有界超时的 `RemoteServerTransport.inspect_batch`；检查链需验证持久化原回执、完整包、原件、业务版本及 worker 已终止。仅实例化检查器或传假回调不构成验收。
3. `scope_verifier.ScopeVerifier` 复用原 `Projections` 来源读取、`UpstreamFlowBinding` 及冻结交接核验，检查控制库/接收库、会话、原大工单、全部所列原文件夹工单、代次及冻结材料；对 Prefect 和来源做前后比较。它不检查所有 LLM 回答内容，也不授予执行许可。来源不完整、已删除、状态变化、未满足“暂停且等待后处理”、LLM 阶段未完成或涉及人工重试的记录导致未知。人工重试现有后处理入口仍不支持终态原工单，不能仅放宽状态判定。本候选会在远端检查前后各调用一次。
4. 没有已通过回执时，`inspect_many([])` 不会访问服务器；装配入口复用同一 `RemoteServerTransport.probe_server(server_identity)` 进行固定身份、随机 nonce 的认证往返。对方窗口报告已在专用隔离账本、受限临时密钥与固定 host key 下完成真实 SSH 测试；那次只证明测试时可联系匹配账本，不证明正式配置已接入、worker 活性、容量或 RAG 已接收。缺失或失败时显示未知。
5. 为结果页接入经过服务器验证的失败和未识别诊断，再恢复相应计数；为处理中接入可信远端活性；RAG 真正接入后需把领取/完成与同一个小工单状态原子对齐。
6. 将本目录 `waiting_api.py`、两个 JS 和 `index.html` 与现有页面资源及可靠身份配置一起安装，并核对加载版本。不得单独替换一部分文件或让旧版本 API/页面回退到本机产物/PID 口径。

现有观察每次可能重新扫描台账、两次核验全部冻结来源并批量重验全部通过回执，服务器每批最多 32 项；多个筛选页使用独立缓存。合成基准：268 个等待文件夹（真实冻结交接核验逻辑，但 Prefect、登记来源和服务器往返是替身）本机两次整次观察约 1.8～3.0 秒；268 份通过回执（来源核验替身、内存服务器回执）共 9 批约 1.0～1.1 秒。它们是两个独立场景，**不包含真实网络、真实材料大小或服务器处理时间**。实际材料多时可能超过 30 秒而持续显示未知或增加服务器负载；单次 SSH 元数据超时和多个批次累计耗时也可能让后台刷新线程占用超过 30 秒。正式接线前须用代表性数据、实际网络和已批准的超时/分页上限核验，不把该观察当作后处理的 8 个运行名额。

测试位于 `tests/`，使用临时数据库、模拟服务器检查、模拟 Prefect 身份和浏览器 DOM；它们不证明真实连接或真实材料处理成功。
