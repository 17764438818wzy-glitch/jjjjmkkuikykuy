## 首轮边界

首轮保留全文身份、结尾 token、字段结构、正文引文和实际步骤校验。字段或引文不合格形成 `FAIL` 回执，属于待复核的技术失败，不能解释为论文质量低。范围外的有效“剔除”、证据不足的有效“暂缓”与技术失败分别记录。只对“入库”论文生成正文索引；Tree / Graph 仍要求来源切片。当前 Wiki 节点没有激活逐篇页面模板，四级 Wiki 导航在已有来源的证据投影通过后构建。

DeepSeek 可能把“入库”论文的范例候选档位留空。此时正文索引和 Tree / Graph 可以完成，但四级 Wiki 的范例投影继续拦截，不能自动补成某个档位。原图只上传保存；图片投影材料按 `naive` 方式解析。

## 首轮结束后的复核顺序

1. 对照预处理批次清单和 `receipts.json`，先确认无上传或解析状态不确定、无身份与哈希失配，再统计主文档及图片回执。
2. 优先复核解析 `FAIL`、有效“暂缓”、入库却缺少范例档位，以及 Tree / Graph / Wiki 证据投影失败的论文。区分网关故障、输出契约错误、真实的材料缺口和范围裁决。
3. 使用原教育 Pipeline 中的 OpenAI 模型，只对需要复核的完整论文做定向检查和修复；对已通过校验且 artifact 完整的论文做分层抽样核查。不得把所有已通过论文无差别重跑。
4. 经复核后再决定是否重解析、补元数据或完善四级 Wiki。重试前核对稳定 `paper_id`、远端文档 ID、内容哈希和现有回执，避免重复上传。
