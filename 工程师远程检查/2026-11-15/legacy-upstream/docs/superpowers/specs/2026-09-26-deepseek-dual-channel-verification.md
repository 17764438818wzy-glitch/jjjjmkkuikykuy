# 教育论文双通道解析：验证与全量运行记录

日期：2026-09-26（北京时间）

设计：[双通道设计](2026-09-26-deepseek-dual-channel-design.md)。实施：[五步计划](../plans/2026-09-26-deepseek-dual-channel.md)。

## 当前结论

通用持久队列及双通道调度已经实现，并已启动教育批次的全量首轮解析。学校 DeepSeek 优先，固定 6 个名额；官方 DeepSeek 补位，固定 2 个名额；总容量 8。自动扩容关闭。单篇技术失败、暂缓或剔除进入各自终态，释放名额继续处理下一篇；未确认写入保留原记录并核查，不重复提交。

这次启用是按照用户明确要求进行首轮批量处理。模型输出契约仍有失败，不能据此声称全部试跑通过或学校最高上限已经确定。校验门槛没有放宽，不合格输出不能生成有效的当前 artifacts 或作为已准入论文索引。

## 已实现的处理规则

- 手动、自动及原教育批次共用持久队列和总容量；重复来源复用稳定任务身份和原远端文档 ID。
- 请求身份与本次执行的模型、供应商、Pipeline、尝试号分开保存。重启后按真实执行绑定核查，UNKNOWN 保守占用容量。
- 学校和官方各自保留容量与故障状态；可信模型节点诊断才触发有限故障转交。质量裁决不自动切换模型。
- 图片与图片投影进配套教育图片库，只上传，不进行图片论文解析。已入库主文档的原有图片回执被接管，缺失图片通过远端核查后补传。
- Tree 从源 Markdown 标题和正文顺序确定性生成；方法 Graph 保留有正文证据的实际研究步骤。历史尝试 artifacts 保留版本，新解析开始时撤回失效的当前指针，只有准入和来源校验通过才发布新指针。
- 旧导入器的常规入口、欠费恢复入口都检查批次所有权，防止旧进程和新队列同时派发。
- 财会知识库及其 Pipeline 未列入本次写入范围。

已明确定位的错误包括：evidence 数量或结构不合格、coverage_token 不匹配、方法名称不在规范词表、research_subject 缺少可定位的正文引文；另有无法从公共接口定位节点原因的 FAIL。失败均保留，没有按低质量论文处理，也没有把旧 meta_fields 的“入库”当成本次成功。

学校 9、12 个名额实验未运行。最新官方八篇仍有失败，严格分阶段试跑驱动按规则停止了后续阶段；用户随后确认可启动全量首轮，因此正式调度只开放固定 6＋2，并关闭增长。此处不能宣称模型输出已经稳定，也不能将 FAIL 终态处理速度当成成功吞吐。

## 已知限制与实施裁决

1. **诊断不可观测**：目前没有可信执行节点诊断读取器。公共文档 FAIL 常不给具体节点原因；不能推断为模型限速，不能自动按猜测换通道。容量满时的官方补位已启用；按已确认模型故障自动转交需要可信诊断接入。代价是部分失败只能留待复核。
2. **费用未知**：公共接口没有可靠的官方 token／费用回执。记录为未知用量及未定价请求，数值汇总中的零不表示免费；如果以后设置有限费用预算而无法预留，调度会阻止新的官方派发。
3. **先批量处理、后验证失败项**：依据用户最新授权，允许固定 6＋2 首轮运行，失败个体被拦下。代价是失败复核积压，尚不能兑现全部论文的成功解析；9／12 扩容实验及最高容量结论延期。
4. **两路同契约**：证据数量、token、词表和正文引文提醒同时加入两路提示词，执行校验代码与准入门槛保持不变，两路归一化契约哈希一致。代价是提示词变化需要重新实测，不能沿用原八篇全通过结论。
5. **旧 Pipeline 身份**：早期教育 DeepSeek v1 只在读取 agent 身份及教育标注拓扑后加入允许范围；历史执行版本记为未知，不伪造过去的契约版本。代价是历史模型/版本信息不能全部恢复。
6. **路径归一化**：迁移后将队列内相对路径一次性转为已核验存在、且处于仓库内的绝对路径，确保后台工作目录变化不破坏来源读取。代价是跨机器迁移需显式重新核验路径。
7. **保留现有工作目录**：本分支包含本次开始前未提交的教育适配模块，继续在现有分支工作并仅提交本计划文件；保留未提交模块和旧 helper。代价是仅 checkout 本次提交不足以重建所有既有教育运行依赖。
