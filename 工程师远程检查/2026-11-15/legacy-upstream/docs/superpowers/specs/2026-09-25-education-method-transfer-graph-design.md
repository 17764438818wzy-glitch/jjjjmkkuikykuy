# 教育论文方法迁移 Graph 与快速首轮链路设计

## 目标

让 Agent 从不同研究主体的真实论文中学习**方法怎样执行、怎样组织成论文**，再将可迁移的操作用于新主体。例如，某一论文中被证实使用的访谈与课堂观察过程，可以作为另一学科或学校论文的写作参照；旧论文的样本、时间、数值和结论不能转给新主体。财会“从偿债论文学习杜邦分析，再用于盈利能力问题”是同一检索原则的例子；本次不改财会知识库或 Pipeline。

## 当前证据与边界

- 教育 v2 一篇已入库样本生成 143 个 Graph 实体、225 条关系，其中 18 条近义 `research_path`，与“每篇一条主路径”相悖。
- 同篇原链路耗时 360 秒；移除 PageIndex 的隔离试跑耗时 423 秒；将原生 PageIndex 缩为仅标题的隔离试跑耗时 684 秒。标题版准确对应原文 70 个标题，但 Graph 扩为 156 个实体。单改 Tree 不能证明提速。
- 现有一次全文标注已保存 `education_research_methods`、`education_method_details`、`education_research_steps`、`artifact_profile` 和原文来源切片。它们是新的方法 Graph 的输入；不重新对全文调用模型抽取 Graph。
- RAGFlow 现有结构图读取接口只提供读取与删除，尚未验证可从客户端写入确定性 Graph。新方法 Graph 先作为独立、可审计的 artifact 和方法倒排索引；不声称它已显示在 RAGFlow 原生 Graph 面板。

## Artifact 分工

研究对象不能从论文知识中删除。它决定材料获取、样本选择和方法适用边界。公共 Graph 不连接具体学校、班级或个人；每篇论文的标注、Profile 与正文继续保留对象、学段、学科和场景。仅有“论文使用方法”关系只能找到文章，不能教 Agent 如何迁移。方法检索必须同时取回该篇 Profile、实际步骤、材料和来源 chunk，形成“研究目的—对象条件—材料—实施顺序—分析方式—适用边界”的实施视图。旧论文的数字和结论只作为来源证据，不作为新论文事实。

| Artifact | 记录内容 | 不记录 |
| --- | --- | --- |
| 方法 Graph | `paper_id` 到受控研究方法的 `uses_method` 边；边指向真实正文 chunk | 年份、时间、人数、分数、百分比、学校/班级名、研究结果；不建论文间或主体间的直接边 |
| 逐篇 Profile | 论文类型、已执行步骤顺序、方法实施过程、材料类别、适用条件、工作量/候选档位、结论边界 | 把旧论文结果表述为新论文结果 |
| Tree | `ingest.md` 的真实标题、原顺序、父子层级、对应正文 chunk | 章节事实/结论的第二轮模型摘要 |
| 四级 Wiki | L1 任务族 → L2 具体论文类型 → L3 经核验的实际路径 → L4 稳定 `paper_id` | 从标题推断执行、不带来源的空目录或百科断言 |

## 方法 Graph 契约

- 每篇一个 `paper` 节点，以稳定 `paper_id` 为 ID。方法节点使用教育域受控名称，例如问卷调查法、访谈法、课堂观察法、教学设计法、行动研究法、前后测比较法、实验法、案例研究法、文本分析法、统计分析法和文献研究法。`混合研究法`是组合标签，分别链接已证实的具体方法；`其他`不建立公共节点。
- 每个 `uses_method` 边都来自标注中状态为“实际执行”的步骤，且该步骤引文可在当前论文的 `role=body` 切片定位。只在方法列表中出现，或仅有设计/计划而没有相应执行证据时，不建该边。教学设计法可由完成的设计方案证明，课堂实施另需实施记录。
- 边保存 `paper_id`、`source_doc_id`、`source_chunk_ids`、受控方法 ID 与 `evidence_step_indexes`。步骤名称通过索引回查该篇已校验标注，Graph 不复制可能带有旧样本数字或具体主体的步骤名称和引文正文。
- 方法节点由不同论文共用，因此通过共同方法间接关联论文。不能因两个论文研究同一学校、学段、年份或主题而自动连边；也不能从某一论文的用途推出方法只适用于该主题。
- 单篇 Graph 通常为一个论文节点、若干有证据的方法节点及相应边。没有可靠方法映射时输出可审阅的缺口，不补造边，也不把技术问题判成论文低质。

## 首轮语料审计（2026-09-26）

- 对 100 篇已入库论文的远端标注与本地方法 Graph 逐一比对：受控词表外只出现 14 次“其他”，均不应成为公共方法节点。因此现在不扩张方法词表；新名称继续进入待审队列。
- 71 个未连方法实例的原因均为“方法列表中有名称，但已标记实际执行的步骤名称未明确对应此方法”；未发现“步骤引文无法落在单个正文切片”的样本。这个缺口是语义证据不足，不是解析技术故障，不因提高召回而自动补边。
- 对已回填的 175 篇执行身份及索引结构检查：10 个共用方法节点、565 条有正文 chunk 来源的 `uses_method` 边，114 个待审方法实例。方法关系只引用当前论文的稳定 ID、远端文档 ID、正文 chunk ID 和步骤索引；不存具体学校、样本数、日期或旧论文结论。
- 当前 Graph 是可核查的独立 artifact 与倒排索引。Wiki L3 路径分类和最终四级导航等教育论文全部解析且技术失败明确处置后再归并，不把这批待审方法实例视作已验证路径。

## 首轮解析与索引

- 建立隔离的教育 v5 Pipeline，沿用 v2 的全文交接、一次完整标注、程序准入、正文切片和全文/向量索引。跳过原生结构编译节点；原有 v2、试验 v3/v4 和财会链路不更改。
- 解析成功后，工作台读取规范 `ingest.md`、远端元数据和正文 chunks，生成确定性 Tree 与方法 Graph，并汇总方法→论文的倒排索引。对每个 artifact 检查稳定身份、原文哈希和来源 doc/chunk ID。
- 原文正文继续提供真正的方法操作和论文写法。检索先从方法索引找到异题材范例，再按 Profile/Tree 找到具体步骤所在章节和正文；Agent 在新主体上重新收集材料、计算和论证。
- 已在 v2 解析完成的论文可回填同样的确定性 artifacts；不重复上传或重新解析。
- 只有隔离样本通过身份、准入、方法证据、Tree 来源、Profile 保留、索引可查和耗时检查后，才将**新待解析论文**路由到 v5。正在运行的旧任务与欠费恢复计划继续使用其已绑定 Pipeline；保留上传回执和不确定写入保护。

## 验收

1. 同篇原文中的实际方法可连到原文 body chunk；计划方法、未验证步骤和具体数据不进入 Graph。
2. 两篇研究对象不同但方法相同的论文，通过同一方法节点能被共同召回；Agent 可回到各自的章节学习操作。
3. Profile 与四级 Wiki 的字段和候选档位不因快速链路丢失；档位空白显示“待核实”。
4. 隔离 v5 解析通过准入与索引，耗时低于同篇 v2 的结构编译路线；若未达到，不切全量。
5. 当前教育知识库、图片知识库和财会知识库的身份、回执与已解析文档保持可核对，技术失败与范围裁决分别记录。

## 首轮落地记录（2026-09-26）

- 隔离样本在 v5 快速链路完成解析约 43.5 秒；同篇 v2 完整链路约 360 秒，保留原生 Graph 的隔离试验约 423 秒。这里比较的是整篇解析耗时，不能把差值全部归因于 Graph 的单独调用。
- 主教育库的新提交文档已指定 v5；原有欠费恢复队列中的三篇旧链路任务继续按已提交状态完成。之后尚未提交的欠费重试在核实原失败原因与文档身份后改绑 v5，不重复上传文档；调度先处理新论文，再使用剩余名额处理欠费重试。
- 对已完成、已入库且已有可回链方法 Graph 的教育论文，按远端模板 ID 精确删除旧原生 Graph。每篇先保存原结构备份和删除意图，再验证 PageIndex 模板、正文切片数、文档身份及状态未改变。已处理的 179 篇有逐篇删除回执和备份。仍在运行的旧任务完成后需要继续同样的清理。
- 远端结构计数比模板内实体总数多一个文档摘要节点；隔离删除验证表明该节点在删前删后都保留。只接受这个精确计数形态，任何更大的缺口停止该篇删除。
- 确定性 Tree 与方法 Graph 当前是独立可审计 artifact；Agent 对方法倒排索引的正式调用以及最终四级 Wiki 导航仍待全量解析和技术失败处理后接入，不将本地 artifact 误称为 RAGFlow 原生 Graph。
