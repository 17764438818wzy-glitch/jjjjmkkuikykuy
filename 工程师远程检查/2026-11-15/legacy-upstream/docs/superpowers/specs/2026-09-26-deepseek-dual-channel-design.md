## 1. 统一契约与两个执行版本

学校与官方共用同一份教育标注、准入、Profile 和切片逻辑。官方版本从经过身份核对的教育快速 Pipeline 复制，只替换生成模型 ID；对 DSL 做结构差异校验，模型字段之外的变化必须失败。

每次解析在提交前持久化通道、供应商实例、模型 ID、Pipeline ID、契约版本和尝试号。运行中固定绑定，不能修改一个共享 Pipeline 来切换全部任务。

图书馆登记名不保证两边是同一实际模型版本。官方旧 Flash 别名与学校别名的实际服务版本由接入记录及同批输出验证说明，不宣称两边输出完全相同。

目录 Tree 继续确定性提取；方法 Graph 继续从已经通过校验的标注与来源 chunk 构建；图片和投影仅上传。Wiki 和方法名称使用相同规范，来源记录保留通道信息。

## 2. 共用持久队列与任务身份

保留现有稳定身份 `(RAGFlow 服务, 目标知识库, paper_id, artifact 角色)`。通道是某次解析的执行选择，不是新的论文身份，不得因此新增主文档。

一个逻辑任务可以有多次明确的解析尝试，但同一时刻最多一个未确认或在执行的尝试。已上传论文始终沿用核验过的远端文档 ID。切换 Pipeline 前核验名称、源内容身份和远端终态。

同一服务下设统一额度控制：学校额度、官方额度、RAGFlow 总额度。自动、手动、旧批次及其他已知调用入口共享相应通道的实际在途计数。学校多个别名不能默认视为独立额度。

新通道先用于已确认的待处理任务。旧批次的接管必须由旧 worker 停止派发、核查远端和回执、持久化迁移记录后完成。未确认提交保持核查状态，不能用迁移或重启清除。

## 3. 学校优先与官方补位

调度时先尝试学校；学校容量已用尽、处于明确限速冷却、认证或服务不可用时，允许官方领取待处理任务。已经在学校执行的任务不因学校饱和而复制到官方。

学校正常容量起点为 6。官方验证起点为 2；两个数字均为待验证的初始配置，不是供应商的最大额度。总额度必须满足服务器实测能力，不能直接将两边模型额度相加后无条件提交。

官方通道支持独立并发、费用统计及预算限制；预算达到后停止新的官方派发，学校通道继续运行。计费数据优先采用真实用量；用量不完整时明确标记估算，不能声称精确费用。配置文档和日志不保存密钥。

## 4. 故障、裁决与切换

| 信号 | 学校通道 | 本篇处理 |
|---|---|---|
| 明确模型上游 429 / 限速 | 降低额度，遵循有效等待信息或有限冷却 | 确认原尝试终态后最多转官方一次 |
| 明确模型认证、欠费或服务故障 | 隔离该通道，记录原因 | 终态已确认时可转官方一次 |
| RAGFlow 接口 429 / 服务器拥堵 | 控制整个服务派发 | 先核查提交结果，不认作学校限速 |
| 网络超时、断线、提交回执丢失 | 不推定模型失败 | 持久化未知状态并只读核查，不再次提交 |
| 明确暂缓、剔除 | 正常释放额度 | 第一轮终态，不自动换模型推翻裁决 |
| 字段、引文或全文覆盖校验不合格 | 记录输出契约失败 | 进入复核队列，不自动当作限速 |
| 仅有队列占位文本的 FAIL | 不根据占位文本降低模型额度 | 裁决不明，进入复核队列 |
| 入库后 Tree / Graph 收尾失败 | 继续补位 | 独立记录 artifacts 故障 |

上游故障信号必须来自受信任的执行状态、节点错误或服务器诊断记录，不能在论文正文中搜索 `429`、`rate limit` 等字符串并当成故障。正文引文、提示词和原始回答不得成为调度信号。

当前公开文档状态可能隐藏节点错误。接入时必须先验证可用诊断接口；取不到模型错误时记录“原因不可观测”，禁止猜测模型限速。明确的 Embedding 故障归属于共享索引依赖，不能通过切换生成模型处理。

## 5. 学校容量发现

先用同组八篇验证官方通道和统一契约，再以有代表性的正常待处理论文进行 6、9、12 等档位的有限实测。比较论文长度、研究类型和已执行步骤完整度；不再用以失败为主的旧样本推算容量。

每档记录实际模型在途数、请求与 Token 用量（可获得时）、明确模型故障率、输出契约失败率、有效裁决数量、成功入库数量、端到端吞吐及延迟分位数。准入裁决与技术故障分开统计；剔除或暂缓只要契约有效可以计为有效裁决，但不得计为成功入库。

调节以有足够样本且实际用满额度的窗口为依据。吞吐提高且故障稳定时缓慢加量；明确限速时快速减量。输出契约失败率升高需要质量诊断，不能直接解释为容量不足。无积压、数据不足或主要任务在标注前失败时，不增加额度。

当增加并发不再改善有效吞吐，或共享服务器出现拥堵，则采用上一稳定档并保留余量。最终运行值只能依据本机与此服务的测量，不照搬官方公布的并发数。

1. 核对官方模型登记、教育 DSL 和诊断入口；保存不含密钥的绑定及差异验证回执。
2. 实现持久解析尝试记录、通道路由、全局在途统计及恢复核查，覆盖并发领取和进程重启。
3. 实现可信故障分类、官方溢出、有限转交、自适应额度及费用/用量状态；提供配置关闭路径。
4. 接入手动、自动和原教育批次；先协调旧 worker，保留全部原回执与原远端 ID。
5. 执行八篇同组验证及二十篇双通道验证，确认字段和证据校验、正常裁决补位、图片只上传、artifacts 来源一致。
6. 在有效输出稳定后进行学校增量容量测试；通过再启用全量双通道运行。

必须有测试覆盖：学校满额时官方补位；重启后保留限速/切换尝试；学校在途任务不被复制；未知写入不被重试；暂缓/剔除不被切换；Embedding 错误不被归为生成通道故障；财会路由不变；旧批次在途任务计入额度；同一身份仅一个主文档；官方不可用时学校继续推进。
