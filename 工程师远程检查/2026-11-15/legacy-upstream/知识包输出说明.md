# 论文知识包输出说明

本次升级只处理本地预处理输出。继续使用现有 RAGFlow 建库、Embedding 和检索；没有开发新检索系统，没有修改 RAGFlow 管道，没有迁移旧批次。

## 使用方式

新程序在重新打开工作台后生效。后续从原文件重新处理，通过的结果自动生成知识包。新版处理标识为 `automatic-v2.5-knowledge`，不会因旧版同源文件已通过就跳过这次生成。

原论文的目录页从交付正文、入库文本和机器知识包中删除，原始文件不动。AI 使用的是从正文生成的真实章节结构。识别结合 Word 目录样式、目录区域、点线页码和正文标题，不因两行末尾有数字就删除。没有足够依据时保留内容。

章节编号用于校验 Word 标题样式；支持常见中英文编号、无空格小节标题和未编号的显式标题。年份、金额和普通列表不会仅因以数字开头而成为章节。缺少上级标题时，不把小节挂到编号冲突的章节下。

工作台中打开通过论文的阅读文档，在文末“写作参考材料”可查看小节文档、结构数据和完整清单。该入口是程序根据正文生成的材料导航，不是原稿目录页。机器文件位于当前批次的 `packages/<文档编号>/`。原来的 `document.md`、`ingest.md` 和 `metadata.json` 入口保留。

```text
<文档编号>/
├─ document.md                   阅读正文，附小节材料入口
├─ ingest.md                     供现有 RAGFlow 上传的正文，内容旁附简短关联编号
├─ metadata.json                 现有处理记录，保持兼容
├─ manifest.json                 AI/程序读取知识包的入口及文件校验清单
├─ metadata/
│  ├─ structure.json             章节层级和顺序
│  ├─ blocks.json                正文块、原文位置和对象编号
│  └─ relations.json             明确引用、原生数据关系及未确定的引用
├─ writing_units/
│  ├─ section_<编号>.md          本小节正文、表格和图片
│  └─ section_<编号>.json        同一小节的有序结构及关联对象
└─ assets/
   ├─ <原图片>.png               已完成脱敏的原始图片或原页裁图
   ├─ tables/table_<编号>.json   表格结构与原值
   ├─ tables/table_<编号>.csv    原表逐行文本值导出
   ├─ tables/table_<编号>.svg    结构重绘预览，明确标记为非原文截图
   ├─ figures/figure_<编号>.json 原图引用、图形结构和数据关联
   └─ equations/equation_<编号>.json 公式表达、原生 OMML 和原文位置
```

只生成实际存在的材料；没有独立公式时不会生成公式对象。结构 JSON 的路径统一相对于整个知识包根目录，方便搬迁到服务器；小节 Markdown 的图片链接相对于小节文件。没有写死电脑盘符，也没有假装原图已经上传到 RAGFlow。

## 后续 AI 和 Skill 怎样读取

1. 读取 `manifest.json`，找到需要的小节 `writing_units[].path`。
2. 小节 JSON 的 `content` 是原顺序内容；`children` 指向下一级小节；`table_ids`、`figure_ids`、`equation_ids` 对应本节引用材料。
3. 根据小节 `objects` 中的相对路径读取表格或图形结构。原图位于图形 JSON 的 `image.path`。
4. 表格的 `dataset.fields` 给出字段及表头路径，`dataset.records` 给出逐行字符串值；原始合并关系同时保存在 `cells` 和 `grid`。
5. 原生图形的 `chart_spec` 记录图形类型、系列、坐标轴、单位/格式等。确认来自同一原生图对象时，`dataset_id` 和 `dataset_path` 指向同一份表格数据；后续 Skill 可用一份新数据同时生成表和图。

图片识别结果的 `chart_spec.series[].chart_type` 单独标明每个系列的绘制形式，例如柱形 `bar`、折线 `line`，并保留 `axis_side`。看不清或旧结果缺少该字段时为 null，不根据指标名称猜测。原生图继续使用 `plots[].type` 和 `series_index_map` 描述绘制关系。新字段在已有图片识别轮次内返回，不增加模型调用。

入库文本只在章节、图表附近放置稳定编号，并保留正文和图表说明。完整区块清单、机器路径及父子关系放在 JSON 中，不再追加整篇区块编号目录。相对路径不代表资产已经上传到服务器。

参考原文的组织方式，生成时使用当前任务的数据。原文数字的 `externally_verified` 为 false，预处理没有替原论文验证财务真实性。

## 几个会影响生成结果的字段

| 字段 | 含义 |
|---|---|
| `paper_id` | 根据源文件内容生成，同源文件稳定 |
| `revision` | 当前完整输出内容版本，内容变化则改变 |
| `source_block_id` / `position` | 返回原始正文位置 |
| `dataset.header_status` | 表头经过确认还是根据结构推断；原行列始终保留 |
| `dataset.numeric_conversion` | 当前为 `not_performed`，原始数字字符串不自动换算 |
| `chart_spec.source` | `native_ooxml`、`ai_visual_observation` 或未知，区分来源 |
| `data_status` | 有原生缓存、视觉转录数据，或未取得底层数据 |
| `explicit_reference` | 原文明确引用某一图表，且编号唯一 |
| `unresolved_reference` | 编号不存在或有歧义，不随意关联 |
| `native_object_data` | 同一原生图对象对应的图像和数据 |

CSV 保留空值和原文本，不将缺失值填为 0；合并格在逐行导出中会展开，准确的合并关系以 JSON 的 `cells/grid` 为准。单位、百分比、数值格式必须结合读取，不能只按字符串强行转换。

## 原貌与结构的边界

- 提取到的原图和批准的原表截图继续保留；与表格匹配尚不确定的截图标为 candidate，不声称已确认。
- 原生 Word 表格的可用 XML 格式结构一并保留。缺少独立原表截图时，提供 SVG 结构预览，并明确标记为重绘，不能当成原文排版截图。
- 普通统计图在已有图片识别中补充绘图字段，不新增全文扫描。可清晰识别的截图表格可同轮提取原样单元格。
- 没有底层数据的图仍保留完整原图、文字和可确认的图形结构，`dataset_id` 为空；不根据曲线估算原始点值。
- 内嵌原生图支持的种类和数据完整性约束沿用现有解析器；复杂或多轴图走已有局部视觉处理，观察不到的字段保留未知。
- 公式保留已提取的原生结构或表达式；没有单独取得截图时，明确记录该状态。

## 本次没有接入的部分

当前上传客户端会上传 `ingest.md`、`ragflow_assets.md` 和知识包内已批准的图片资产到同一个 RAGFlow 知识库。JSON/CSV/SVG 作为本地知识包的结构侧车，由 `ragflow_assets.md` 提供可检索投影；图片作为独立文档保留原始视觉信息。每个辅助文档的远端编号和状态会写入批次清单，供重试和解析任务使用。

通过知识包只代表本地预处理达标。原来的会计研究主体、研究方法、研究内容、方向、人群评级等后续标注流程维持原职责。
