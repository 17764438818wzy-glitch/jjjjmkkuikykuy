# 论文持续处理工作流设计

状态：用户于 2026-10-16 明确批准实施。本文记录完整工作流，不只定义模型调用。

## 目标与范围

在电脑上持续接收现有管理学、法学原稿，接管可验证的未完成成果和问题稿。三轮业务 LLM 完成原文理解、补正与专业选择、图表说明/脱敏/切片；本地工具落实处理。RAG 接收处理结果、完成向量化与索引并提供检索。无 100 篇停止规则，无新增语义质量门槛，不按评分只保留少数文章。不考虑 DeepSeek 金钱成本，以可靠完成量和资源约束调速。

现有 E:/uv/ragflow_upstream 有大量用户未提交改动；E:/rag mid/pipeline/ragpipe 也已有旧脚本。新增工作流隔离在本目录，不覆盖这些实现及其数据库。保留所有原稿、旧任务及旧成果。

## 主流程

目录监听 -> 文件稳定性/内容身份登记 -> 成果与入库回执对账 -> 新稿或断点队列 -> 第一轮 -> 第二轮 -> 第三轮 -> 原子发布 -> 固定技术检查 -> 入库队列 -> 各目标专业Send分支写入 -> 实际读回 -> 完成回执/当前版本切换 -> 临时文件清理。

模型节点需要工具读取全文及真实图片；不能在模型处理结束后才读取原稿。前两轮沿用用户原有两份提示词，保存原文快照及哈希。追加明确的交付协议和本次更新：第三轮处理图片、脱敏和切片；图表用于学习研究用途/指标关系/方法/所需新材料，不要求逐项复制旧数据；原稿不可修改。原提示词中的批次限制、删除原稿、第三方语义审批由本次批准设计覆盖。

图表三分流：描述足够的只发布说明；视觉结构不可替代的发布原图与说明；装饰与重复图不发布。说明与资产均关联论文、章节及原文定位。正文与学习说明区分，正文已有数值不擅自改造，图表学习说明不强求逐数值抄录。

## 调度、持久化与版本

LangGraph 检查点是单篇内部进度的唯一依据；SQLite 台账保存原稿/修订版本、租约、due、远端回执及激活事实。台账stage只是调度用副本，节点提交后由检查点同步，已删除step_seq对齐。恢复使用原生invoke(None)接着pending后继执行；图提交而台账未同步的中断窗口只同步副本，不重做业务节点。外部接管/唤醒写控制请求，由图接受，不直接改内部阶段。台账写回有version乐观锁，只同步必要调度字段，冲突保留外部修改并按owner释放租约。

第三轮已拆为round3_assets→round3_redact→round3_chunk。各子节点记录输入文件指纹与输出目录，并校验产物散列后复用；缓存随自有work清理。切片故障仅回切片。修复节点只修复，之后回business_stage重新执行该阶段，再继续全部后继；业务阶段不允许repair值。

新稿优先且为修复保留容量。无任务时等待；新文件稳定后自动加入。资源不足或入库积压时停止新增模型工作，已有入库/查询工作继续，恢复后自动推进。进程锁防止双实例。重启回收旧租约，从未完成节点继续。

身份包含原稿内容哈希、处理协议版本和修订版；路径或文件名不能单独证明相同内容。新原稿版本建立新任务，不覆盖已有交付。新版全部目标成功后更新当前版本登记；远端旧版停用也必须读回确认。无法可靠停用时不得把新旧混用报告为完成切换。

## 交付及技术检查

每版使用独立临时目录，所有文件写完再生成 manifest，READY 最后发布，再原子重命名到交付目录。已发布修订不可原地修改。支持现有 results 和 Updated manuscript 的 rag-mid/1.0 交付，归一化清单字符串/对象等已知结构差异，但不静默忽略缺文件或哈希冲突。

第一轮沿用原提示词的材料类型、学习价值和适用层次判断：保留的论文或有价值附件继续；明确排除材料、暂无法判断材料分别保留结果和理由，单篇暂存。适用层次/人群不是全库质量排名，局部不足记录受限用途，不自动拒收整篇，也不只收几百篇。原件均保留。

技术检查不用 LLM，检查身份、完整标记、文件哈希/可读性、路径是否越界、JSON结构、切片/章节/资产引用和目标库映射。增加公开文本的手机/邮箱/身份证/带标签学号残留检查，并按private/redaction_map.json逐项检查LLM识别的敏感字面量。公开研究对象允许保留；错误摘要只写文件/规则，原始命中留私有诊断。没有新增语义评审。原作者数据差异、方法不足、模型尚未执行程序检查等unresolved_issues是备注；只有明确导致无法交付的processing_blockers才需要处理。

## 入库与确认

复用现有 RAGFlow 原生请求接口、DPAPI 凭据读取和专业目录。每个三级专业独立，目标库只从既有目录映射。优先直接写入准备好的切片，必要图片使用带说明的图像切片，不重新触发整篇 PDF/Word 的重型解析。画像、章节树及来源关系既有结构化元数据也有可检索内容。

完整画像和章节树保留在标准元数据中；检索索引采用既有字段投影、目录索引及模型生成的学习切片，避免把数万字诊断重复作为单个大切片向量化。此处只映射已有结构，不由程序另做语义分类或语义切片。

发布前记提交意图；每个远端对象用内容/版本身份命名并绑定元数据。超时后先查询身份与实际内容，再决定补发，不能仅按文件名认定已成功。分页查询 page_size <= 100。逐目标确认正文/学习切片/必要图片/关联及检索可见性；全部成功后才记整篇完成。只重试失败专业和未完成对象。

## 修复闭环

内容、格式、缺失与关联故障 -> failed manuscript 下写问题包（原稿引用、任务、错误、原成果及远端身份）-> DeepSeek 修复 -> 新版 Updated manuscript -> 技术检查 -> 再入库 -> 成功后关闭问题。

网络、模型服务或 RAG 暂时故障不调用内容修复，按退避重试原步骤；代码/配置异常单列，避免假冒论文错误。同类内容错误连续三次且已验证阶段未前进时暂存；仅改文件字节不算有效进展。原稿、工具或修复规则变化后重新激活。自身失败包不被扫描器再次导入；外部新修复 READY 可以接回技术检查。

## 接管、空间和操作

先接收现有任务与 READY/故障包，已有回执仅在身份和实际远端结果吻合后采信。已成功阶段复用；存在变更和冲突时只停该篇。历史仅有进程退出或 parse_complete 字样不能作为成功证据。

默认启动界面只展示状态，不自行开始全量工作；提供开始、暂停新增、继续、停止、查看问题。停止等待当前技术写入收尾并保存进度。只有所有目标完成且回执持久化后才清理明确归本次任务所有的可重建临时目录，原稿/有效成果/最小回执保留。清理必须限定在工作流自己的目录中。

## 验收

正常稿、图表稿、问题稿修复回流、断点重启、同名不同内容、网络超时后查询去重、跨专业部分失败、新版本切换、损坏/路径越界交付、无进展暂存和积压限速均有行为验证。先离线及本地 HTTP 故障注入，再有限真实模型与现有目标库验证；不启动全量或改服务器配置来代替验收。吞吐以成功原稿/小时、阶段耗时和资源为准，不把并发配置或 GPU 利用率当成完成量。

## 架构方案落实细节

业务流程为round1→round2→round3_assets→round3_redact→round3_chunk→publish→validate→ingest→各专业ingest_target→join_targets→activate→cleanup。legacy round3只作无模型的子节点入口。

repair回原business_stage。若原阶段消费不可变交付包，先经publish_repaired发布修复的新修订；原阶段为verify/activate时先写入新修订，再执行该消费者，不复用旧版回执。第三轮子节点校验输入与输出散列才复用，切片故障不重做图表/脱敏。

模型可能按原提示词将最终专业名单只写入corrections。程序仅将模型明确的final_routing_candidates机械同步到profile，两个模型名单不一致时拒绝，不由脚本重新分类。

分类基础设施故障使用节点短RetryPolicy和台账due长退避；代码故障停止单篇；内容修复保留业务原点。JSON语法同会话最多两次局部补正，不增加业务revision或repair_count。图表与脱敏的私有映射指针通过检查点保留，公开产物残留检查纯程序执行。

远端回执以(task_id,revision,code)独立存储。服务器enabled=0的文档不可检索，因此分支先做隐身写入与精确读回；全部准备好后激活阶段临时启用、逐类别检索验证，再停用旧版和提交活动台账。单次API无法跨文档原子切换，异常由持久激活意图补偿；只有最终读回均正确才报告完成。

旧版回收需要当前活动新版持续稳定7天，覆盖移出专业；仅删除完整身份、停用状态及切片SHA均与退休回执吻合的对象。无法证明身份的旧对象保留并记录故障。删除意图持久化，删除后再读回。维护和业务共享RAG名额，并统一先取RAG名额再取激活锁。

持续启动前验证全部验收记录与当前代码/提示词/依赖声明/专业目录散列；UI默认不自动运行。有限测试库标定1/2/4路时吞吐已平台，选择默认RAG并发1、LLM并发2，后续可重新标定。
