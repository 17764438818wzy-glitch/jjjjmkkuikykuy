# 用途初筛与 LLM 复检

已授权：仅修第三项，在统一源码目录实施；真实文件隔离验证；不启动任务，不改论文审核规则或已有结果。用户指定原地址、专用密钥、gpt-6.1-sol / max。

程序全局扫描只建立文件、项目和格式索引，不转换 Office、不 OCR、不调用 LLM。每个文件在工作槽内读取一次用途证据，LLM 直接复用该证据；同哈希、同用途规则和同模型的结论缓存复用。明确 CAD/源码无需 LLM；PDF、Word、扫描图片及文本正文须复检，程序自信判为正文或删除也不豁免。

分类输出 body / attachment / administrative / mixed / unknown，记录证据编号和实际阅读覆盖。正文进原审核；附件保持原件并关联同一项目的唯一正文；只有完整覆盖且排除正文及有效附件的独立开题报告、任务书、答辩记录、审批表等可删除。冲突、混合、不完整阅读、接口失败必须保留，不自动重发不确定请求。

删除二次核对哈希和路径，不动已有结果、回执、请求记录。原始混合压缩包不能整包删除：清理按明确成员决策生成干净包，逐个核对保留成员；绑定既有回执的源包只列待人工确认的清理项，不能隐式破坏来源。后台旧上传计划不增加 LLM 调用、不重写。

附件定位限制在同一学生/项目；未复检、多正文及跨项目候选不强关联。正文解析失败显示正文待解析，不改变用途。

完整继承当前 stop-fix-20261022 的 14 个模块和 token 节约更新，不调整停止机制、500 分组、正文思考强度或画像。

验收使用两份错误图纸合集、两份主修计算书、两份长开题报告、扫描答辩记录、混合包及正文提到任务书的反例。实际原件只读；删除与包清理仅在隔离副本执行。记录准备时间、请求时间、缓存命中、真实 token 和模型身份。路由放行后已确认 gpt-6.1-sol 可用，使用 max；未使用 Astra 备选。

新附件计划使用 /2，兼容读取历史 /1。新批次自动入库开启时，如同一数据根目录的旧 uploader 尚未自然退出，明确显示等待原因并允许取消；不停止、重载或修改旧上传。所有未知用途先保留待确认，不能显示成已确认附件；已确认正文的复检失败保持正文待复检，不能绕过复检进入论文审核。
