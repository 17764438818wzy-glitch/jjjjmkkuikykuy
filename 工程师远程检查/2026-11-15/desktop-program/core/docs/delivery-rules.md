# 已确认的交付检查规则 v2（2026-10-17）

用户已批准实施。内容以“能读取、能使用、能正确入库”为标准，接受非关键缺项和合理误差。本版覆盖历史文档中过严审核、一次补正及空图表说明一律放行的旧规定。修改后保持停止，未恢复入库。

## 内容判断的归属

内容判断采用 DeepSeek 在约定阶段的最终结果，不增加人工或 LLM 质量复审。第一轮材料性质筛选保留：排除、暂无法判断仍走原分支；保留的文章不再参加总分排名、前几百篇筛选或专业数量限制。图表描述优先，确有必要才保留图片。主要学习结构、方法、分析关系和写作流程，新写作自行取得新数据，不要求逐项重抄旧图表数值。

## A：必须拦截的实际交付故障

“拦截”是明确机械修复和允许的定点补交后仍不能解决时暂存；身份冲突、封包字节异常直接暂停，不能猜补。单篇或单目标失败不拖住其他文章。

| 编号 | 情况 | 执行边界 |
| --- | --- | --- |
| A1 | 必需文件不能读取 | 必需 JSON 严重损坏或内容截断，安全格式处理仍无法恢复。辅助诊断、补正说明、脱敏映射损坏或缺失不单独拦截。 |
| A2 | 必需内容实际缺失 | 正文为空、处理后正文在正文切片中实质遗漏/重复/截断；画像或适用的章节结构完全缺失，且无现成明确内容可恢复。明确不适用章节的附件、代码、图纸、数据资料不强制套论文结构。只核对处理后正文的交付完整性，不逐字复审原论文。 |
| A3 | 无法确认同一篇文章 | 任务或来源内容身份冲突、混入别稿、已封装字节发生无法解释的变化。封包只读核对，重新发布前先验证原封包，不能覆盖身份或重算哈希掩盖变化。 |
| A4 | 无法确定目标库 | 专业代码无法对应现有目录或必要库映射缺失。有效专业继续，故障专业保留待处理项；不能猜库，也不能整篇报完成。 |
| A5 | 必要图表未交付 | DeepSeek 决定必须保留的图片不存在；选择描述但描述为空，且同一图表没有现成说明可复用。仅不抄全旧数值、未保留不需要的原图不拦截。 |
| A6 | 明确私人身份未处理 | 仅明确作者联系方式、作者元数据中的学号等，或模型给出的准确字段/行位置。能安全机械替换则替换，仍残留或定位冲突才拦截。普通号码、研究字段里的学号、参考文献同名、公共对象或代码示例不因此否决。 |
| A7 | 实际入库未成功 | 写入、读回、必要图片、目标库或索引/检索未确认，不能标记完成。网络及服务器故障走技术重试，不让模型改文章。 |

## B：程序优先完成的明确机械修复

| 编号 | 情况 | 修复边界 |
| --- | --- | --- |
| B1 | JSON 包裹/编码/明确语法差异 | 读取 BOM、移除外层代码围栏及字符串外无歧义尾逗号；不猜补截断内容，不删正文换通过。 |
| B2 | 已知别名/结构包装 | 兼容列表包装、text/markdown 内容及编号；保留字段和非空内容，不重新判断研究含义。 |
| B3 | 程序应生成的身份与清单 | 补缺失任务字段，生成交付清单和哈希；已有任务/来源冲突必须暂停。不可变包先验证再复制处理，原包不改。 |
| B4 | 专业名称/副本差异 | 以有效代码规范名称，重复专业去重；同步第二轮明确交付的完整最终专业名单。 |
| B5 | 切片边界明确但内容未填 | 按 LLM 的连续行边界复制最终正文，不让模型重抄；不自动猜测或移动边界。 |
| B6 | 明确图像定位/身份定位未落实 | 按已确定图像定位复制必要图片；按准确字段或行位置替换身份，正文与逐字对应切片同步，包括跨切片位置。准确映射优先于其覆盖的机械标记，模型定位互相冲突时不任选。 |
| B7 | 中断/回执丢失/索引未就绪 | 先核对服务器已有结果再补传或重试；按目标保留成功回执，只处理未完成目标。 |

不存在现成内容时，程序不能伪造画像、章节、图表说明或正文。修格式只修格式，补交只补当前明确缺项，不重做成功的业务阶段。

## C：可以备注但直接放行

| 编号 | 情况 | 处理 |
| --- | --- | --- |
| C1 | 合法 JSON 的缩进、顺序、换行及无害额外字段 | 正常读取。 |
| C2 | 非关键字段缺失、局部章节/图表编号关联不完整 | 主体仍可理解和检索时备注，不返修。 |
| C3 | 原稿错字、旧数据差异、方法不足或局部论证问题 | 采用模型使用限制，不复算、不提高准入门槛。 |
| C4 | 无明确私人身份语境的号码/邮箱等样式 | 仅作不含原值的备注，不凭格式否决。 |
| C5 | 企业、机构、地区、公共研究对象、参考文献署名 | 保留，不扩大脱敏。 |
| C6 | 按模型规则存描述，没有原图或旧数值未抄全 | 放行；无留图时不要求无用的图片库配置。 |
| C7 | 多专业、学历未知、仅部分内容可学习 | 采用模型判断，不设专业数量上限或总分排名。 |
| C8 | 模型警告、疑虑、processing_blockers | 看是否构成 A 类实际故障，字段本身不触发返修。 |
| C9 | 切片超过建议字数但实际接口可接受 | 放行；真正超过接口容量只处理容量问题。 |

## 两次累计补交与重试

每篇额外定点补交累计最多 **两次**，JSON 格式补正与交付补正共享额度。调用前持久记录；换版本、换报错、服务异常或进程重启不能重置额度。正常业务轮次不占额度。机械修复不调用 LLM、不占额度。

同阶段 JSON 问题优先在原会话修正，不新增版本；真正需要交付补交时按已有失败阶段定点修复。成功后更新产物指针，继续其后继步骤，不再调用已完成的同业务阶段。两次用完仍失败就保留成果暂存。网络、服务器写入/读回及索引故障另走有界技术重试；程序 bug 暂停该篇并保存诊断。

## 部分完成与真实完成

“部分完成”是从当前修订逐目标回执计算的显示状态，不新增或覆盖 LangGraph 的真实调度阶段。显示已写入核对、已确认可检索和待处理目标。旧修订回执、仅有写入意图、缺实际文档的记录不计成功；未激活的修订即使写入/索引已核对，也不显示为已可检索。

存在故障目标或待验证/待切换状态时不能整篇标完成。全部目标通过且版本切换、应有收尾完成后，沿用既有完成流程。

## 验证与停止边界

复用现有 pytest、真实 LangGraph/SQLite/封包逻辑及本地 HTTP/内存服务替身验证；不调用真实 DeepSeek 或知识库。完整离线回归及停止检查保存在 `runtime/rules-v2-verification-20261017/`。既有原稿、不可变交付、检查点和回执不迁移、不重写；STOP_TRIAL 保持有效。
