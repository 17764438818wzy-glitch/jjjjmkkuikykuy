# 教育论文研究范例链路设计

## 目标与状态

为桌面“`小学教育`”文件夹中的教育相关论文设计一条共用的研究范例链路。链路应从完整、脱敏的原文出发，产出可追溯的 Tree / PageIndex、实际研究路径 Graph、四级 Wiki 导航和全文／向量检索索引。使用者能够找到适合自身题目与工作量的写作范例，并回到原论文的章节和 chunk 核查；旧论文的数据与结论不能转作新研究的事实。

本文件记录设计及首次试跑准则。用户已授权从通过预处理的论文中自选八篇试跑；实际部署、解析状态与失败记录另见试跑记录。财会知识库和“财会论文研究范例链路 v1”均不修改。四级 Wiki 的详细词表与证据规则见 [教育论文四级 Wiki 分类设计](2026-09-24-education-wiki-four-level-design.md)。

## 已确定的决策

- 教育专业共用一条逻辑 Pipeline。专业、学段、学科、教育场景作为标注与检索维度；物理知识库的分流不能改变统一的分类 ID、`paper_id` 和证据约束。
- 整个“`小学教育`”目录是候选池。入库须同时满足教育研究问题、可读原文、已完成的研究工作和可定位的正文证据。体育教育等专业中与教育过程无关的论文不进入本链路。
- 沿用财会链路的处理骨架、三档范例候选与来源追溯机制；教育方法、准入及档位规则单独制定。旧 Wiki 模板不视为现行配置。
- Graph 表示论文实际怎样完成研究。Tree 保留原文结构。Wiki 是由已入库来源构成的导航，不独立生成无出处的百科文章。

候选专业族包括目录中实际出现的小学教育、教育学、学前教育、特殊教育、体育教育、音乐教育和汉语国际教育；按学校归档的小学教育论文归回小学教育。后续遇到教育技术学、职业教育等材料，可按同一教育问题准则进入候选，不凭专业名称自动入库。来源专业与正文研究的教育场景分别标注。

## 端到端流程

```text
只读原文件
  → 本地预处理与专业粗分、正文／原生图表提取、图像识别、脱敏、缺口记录
  → 稳定身份与上传回执、教育 md／图片知识域分流
  → ingest.md 文件解析与全文交接校验
  → 一次完整论文标注（教育字段、质量裁决、artifact_profile）
  → 程序证据校验与准入
  → 正文切片与来源锚点
  → Tree / PageIndex、教育研究路径 Graph
  → body、index、assets 角色索引与全文＋向量检索
  → 知识库级 Wiki 增量任务，生成四级导航
```

只有主文档 `ingest.md` 触发论文解析。`ragflow_assets.md`、图片投影及原图承接辅助材料角色，记录回执且不冒充论文正文。预处理不做学术质量或学历适配判断。缺失或未可靠恢复的对象带入下游，由准入规则判断其是否影响必要证据；技术故障保持独立状态。

### 阶段一：身份、交接与全文校验

以原始源文件哈希导出的稳定 ID 贯穿 `manifest.json.paper_id`、图片投影及教育链路的远端上传回执。现有财会 Pipeline 将 `paper-handoff/1.0` 中的 `paper_id=AUTO_...` 用作预处理任务编号，还会将其与文件名核对；为保持兼容，交接块保留这个旧字段，并新增 `stable_paper_id` 与清单的 `paper_id` 相等，另明确 `document_id=AUTO_...`。教育 Pipeline 使用 `stable_paper_id` 作为论文主键，同时核对两个编号的关系。RAGFlow 还须校验全文哈希、结束覆盖标记、缺口列表、隐私状态和正文长度／末尾覆盖。校验不能证实全文时进入技术暂缓，不据此判论文质量低。

当前批次的只读核对发现：`manifest.json.paper_id` 来自 `paper_identity(meta)`，交接块的 `paper_id` 是 `meta.get('id')`；所检已通过知识包均不相等。上述新增字段是教育链路的兼容方案。首次解析前须在试跑副本中核对 `stable_paper_id == manifest.paper_id` 且 `document_id == handoff.paper_id == manifest.document_id`；未通过时停止上传。财会 Pipeline 的旧字段含义不改变。

### 阶段二：一次完整教育论文标注

标注以完整正文为依据，产出一个版本化记录 `education_annotation/1.0`，至少包括：

| 字段组 | 最低内容 |
| --- | --- |
| 身份与范围 | `paper_id`、来源专业、教育问题、是否属于教育研究 |
| 教育场景 | 学段、学科、教学／管理／家庭等场景、研究对象及角色；学校和班级信息按脱敏状态保留为来源属性 |
| 论文结构 | 研究问题、具体论文类型、方向、章节任务、结论和适用边界 |
| 实际研究 | 按顺序列步骤、实际／计划／不明状态、材料、对象、工具或量表、分析要素与结果 |
| 裁决 | “入库／剔除／暂缓”、原因、技术状态；`artifact_profile`、范例候选档位及依据 |
| 来源证据 | 每个关键字段所依赖的原文引文、章节／block 定位和原文状态 |

“实际执行”不能从方法清单、摘要、绪论计划、参考文献或标题推断。问卷要区分设计、发放、有效回收和分析；访谈要区分提纲与实际记录；观察要有对象、记录与分析；教学设计要区分方案与课堂实施；行动研究要见到轮次及反思；干预要分别核对前测、实施、后测和比较。单组前后变化不得自动升格为因果结论。长文可按原文章节确定性装包并合并为一份完整标注，任何装包方式均须证明全文覆盖；模型调用次数不写死。

`artifact_profile` 明确记录具体论文类型、实际研究路径、实际材料、研究问题、方法目的／步骤／数据、写作套路、适用条件、工作量、范例候选档位及依据，并逐项附原文证据。优先复用完整标注生成 Profile；若还需模型整理，常规论文以一次调用为目标，长文最多三次，超预算时记录技术暂缓而不捏造缺失字段。

### 阶段三：程序校验与准入

程序核对字段结构、受控词表、全文哈希、覆盖标记、引文是否能在原文定位、步骤与材料的关系以及结论是否超出已执行路径。对以下状态分开记录：

| 状态 | 处理 |
| --- | --- |
| 入库 | 教育范围明确、正文证据足够、关键材料可追溯；继续构建 artifacts 和索引 |
| 暂缓 | 范围或方法证据不清、必要对象有缺口、引文冲突；保留原因供复核 |
| 剔除 | 明确非教育论文、无足够论文正文，或其自称类型所需工作未完成且无法归入其他有证据的类型；结论严重脱离材料亦属剔除依据 |
| 技术失败 | 解析、模型输出、哈希／覆盖或服务故障；重试或修复后重判，不计为论文低质 |

质量准入与范例档位分别判断。仍用函授、普通本科、重点本科三个适配候选，但以教育研究的完成度、可复用的写作路径、材料分析和工作量为依据。描述性调查可形成高质量范例；形式上复杂的统计方法本身不保证高档位。适用人群沿用财会的直接映射，不递归扩展；不含硕士。

### 阶段四：切片、Tree 与 Graph

正文切片保留原文段落、标题层级、表格和图像来源 ID，chunk 与 `paper_id`、`section_id`、`block_id` 可互相回链。Tree / PageIndex 按原章节顺序生成，并对章节标注研究背景、理论／文献、设计、材料采集、实施、分析、反思、结论等任务；任务不明确时记录未知。Tree 不重排原论文，也不把建议章视为实施章。常规情况下采用结构化轻量生成，不额外逐章调用模型。

Graph 联合抽取实体和关系，实体为 `paper_type`、`research_path`、`education_context`、`research_step`、`material`、`analysis_element`。关系至少支持类型使用路径、路径包含已执行步骤、步骤使用材料、步骤分析／测量要素、步骤先后、路径适用教育场景。每条边必须附论文、章节、chunk 和引文。只有已执行步骤进入公开 Graph；计划或不明步骤留在 Profile。学校名、年份和学生姓名不扩成跨论文公共实体。Graph 按完整来源文本装包，调用次数由长度和上下文预算决定，记录每次装包范围；失败记为部分结果，不报告“全部成功”。

首次试跑发现，当前 RAGFlow Graph API 输出的关系只有起点、终点和类型，缺少逐边来源字段；长文分包装包还会生成近义 `research_path`，个别论文也出现两个 `paper_type`。因此原始 Graph 只能作为候选视图。正式发布前需要用单篇标注的主类型／主路径做归一审查，并为每条保留关系建立可定位的正文切片证据；仅凭两端节点有共同切片也不等于关系已经得到证明。

### 阶段五：四级 Wiki 与检索索引

Wiki 按“研究任务族 → 具体论文类型 → 实际研究路径 → 范例论文”组织。L1／L2 是版本化受控词表，L3 仅由经校验的已执行步骤形成，L4 仅挂接“入库”论文。专业、学段、学科、研究对象和档位作筛选字段；每篇有一个主挂接及证据支持的交叉链接。当前 RAGFlow 的 Wiki 模板是知识库级模板：文档 Pipeline 完成解析和索引后，由知识库 `index?type=wiki` 任务增量生成页面，不能把逐篇 Compiler 的成功当作 Wiki 成功。先在试跑中核对来源和页面，再对一批已入库论文合并同义路径、检查错挂与空目录。

六篇试跑还暴露出多文档 Wiki 页面可能只引用其中一篇正文的问题。因此四级目录应由已校验标注和身份清单确定性维护；生成模型写的 Wiki 页面仅作为候选说明。发布门槛必须逐页证明：每个 `source_doc_id` 都有该页实际引用的可用 `body` 切片，L4 与稳定 ID、档位候选一一对应，且页面事实与原文不矛盾。缺一则保留审查状态，不自动挂入正式导航。

索引保持三种角色：`body` 是可引用原文，`index` 是 AI 标注与结构化检索字段，`assets` 是图表／图片参考材料且不能独立支持正文研究结论。沿用全文＋向量混合检索及现有 `text-embedding-v4` 作为首轮基线。查询先按意图使用 Wiki 导航、Graph 路径或 Tree 章节，再以专业、学段、学科、材料、档位过滤候选；最终答案必须引用真实文档、章节与 chunk。检索可展示旧论文的工具结构或写作步骤，但不得把其样本数、比例、访谈原话、前后测分数和效果结论用作新论文事实。

试跑验证中，`body` 块可用作来源；`index` 与 `assets` 块在主文档保留，但设为不可用作来源，Wiki 只读取可用正文块。图片材料另存图片库。

当前检索 API 默认会混入 Graph 等编译结果。需要引用论文原文的最终检索应显式传入 `include_knowledge_compilation=false`，再按 `education_stage`、`education_subject`、`artifact_example_tier` 等文档元数据过滤；Wiki 和 Graph 可作为找范例的导航线索。Wiki 模型看不到预处理稳定 ID 与候选档位时，须从已校验的远端文档元数据补齐，并复核页面引文确实对应可用正文块。

## 首次解析方案

从当前已完成、通过预处理的知识包中选八篇，覆盖现状调查、教育实习、教学应用、训练效果、教学设计及教育范围边界。为运行中的批次制作独立试跑副本，不改写其原知识包。先解析一篇含问卷调查与实际结果分析的论文，检查整条链路；通过后再提交其余七篇。边界样本用于检验“剔除”判断，不预设入库，不为试跑放宽准入。试跑只使用隔离的教育 md／图片试验库和教育 Pipeline。

试跑开始前的阻断检查：

1. 清单、交接块 `stable_paper_id`、辅助材料和试跑上传回执使用同一稳定论文 ID；旧 `paper_id` 与 `document_id` 一致；文件哈希、覆盖与缺口状态可读。
2. 文本和图像隐私检查通过，特别核查学生、教师、学校和照片的可识别信息；失败文件不上传。
3. 教育试验库、Pipeline、模型账号和索引模型已单独绑定，配置中无财会库或财会 Pipeline ID。

试跑验收以可核对结果为准：

- 标注正确识别调查对象、问卷设计／发放／回收、可能的访谈和实际分析，不从标题臆造课堂干预。
- 程序能在原文定位关键引文；“入库／暂缓／剔除”和技术状态可解释。
- Tree 保持原章节顺序；Graph 的每条实际边有证据；Wiki 出现一条正确的四级路径且 L4 指向同一 `paper_id`。
- `body`、`index`、`assets` 角色分明；以“找小学现状调查问卷范例”“论文怎样分析社团开展问题”等查询能返回原文章节和 chunk。
- 记录解析时长、模型调用次数、Graph 完成状态、上传回执和失败原因。任何部分失败标为部分完成，不据此宣布链路验收通过。

八篇能检验本批现有的调查、教学应用、设计与范围边界；当前已完成包没有足够可靠的课堂行动研究和前后测组合样本时，后两类另行补测，不从题名推断实施。

## 设计验证与剩余边界

本设计依据现有财会链路交接说明、`README.md`、`knowledge_package.py` 及教育论文抽样。线上隔离试跑已执行，详细回执与未通过项见[首轮八篇试跑记录](2026-09-25-education-pilot-review.md)。六篇完成索引，两篇遇到解析技术失败；自动 Wiki 的多文档证据覆盖与 Graph 的类型／路径归一仍需改进。因此本设计明确区分已验证的文档处理能力、待审的编译候选和未通过的正式导航门槛，不预设固定每篇模型调用次数或吞吐量。
