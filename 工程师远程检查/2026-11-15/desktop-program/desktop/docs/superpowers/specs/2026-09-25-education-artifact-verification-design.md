# 教育论文 Artifact 核验层：二十篇扩样设计

## 问题定位

首轮八篇试跑中，六篇完成正文索引与 PageIndex，两篇解析技术失败。RAGFlow 原生 Graph 从同一篇论文抽出近义的多条 `research_path`，关系 API 只有端点和类型，没有逐边来源。知识库级 Wiki 任务虽登记五篇 `source_doc_ids`，一个页面正文只引用其中一篇；任务最终标记一页失败。模板提示词已收紧过多轮，问题仍存在，因此不能把原生页面的来源清单直接视为论证覆盖。

现行 RAGFlow API 允许读取和编辑已有 Wiki 页面，没有经公开接口创建带来源关系的新页面的方法；[页面编辑接口](https://github.com/infiniflow/ragflow/blob/main/api/apps/restful_apis/dataset_api.py)也明确说明不会同步刷新 Canvas 等关联行。由此，试验库的原生 Wiki 页面保留为诊断产物，不作为通过核验的四级导航。正式接入 Artifact 页需要后续在 RAGFlow 服务端实现经过校验的页面/关系写入，或者提供等效的受支持导入接口。

## 核验层

扩样仍只用隔离教育试验库。每篇入库论文从远端读取 `meta_fields`、全部 chunk 和 PageIndex：

1. 对照试跑知识包清单、上传回执和远端 `education_paper_id` 校验同一个稳定 `paper_id`；只接受 `DONE` 且 `education_admission=入库` 的论文。
2. 只用 `role=body` 且 `available=true` 的 chunk 定位每个“实际执行”步骤的连续正文引文。一个步骤无法定位则整篇投影暂缓。计划、不明和建议步骤不进入路径。
3. PageIndex 章节实体必须都回到该篇可用正文 chunk；原有章节实体与关系原样保留为 Tree 产物，不按研究路径重排章节。
4. 每篇只生成一个具体 `paper_type`（来自已准入的论文 Profile）和一个归一 `research_path`。Wiki 的 L1/L2 来自受控词表，L3 由已核验实际步骤提炼并在逐篇分类表记录；完整步骤序列仍单独保存。材料和指标仅在同一步骤的已定位引文明确提到时建立边。每条投影边带本篇 `paper_id`、远端文档 ID 和来源 chunk ID；不把原生 Graph 缺少来源的边补写成已证实。
5. 四级导航由这些投影确定性生成：任务族 → 论文类型 → 归一路径 → 稳定 `paper_id` 范例。L4 标示候选档位、文档和正文 chunk；未完成、范围外、待分类或证据校验失败的论文不出现在核验导航中。
6. 新研究必须重新采集样本、问卷、访谈、观察、课堂实施和测量数据，重新验证结果。范例档位仍是函授、普通本科、重点本科候选，不是学校审核结论。

## 扩样与验收

试验清单从八篇扩至二十篇，其中新增十二篇小学教育论文，覆盖调查、策略、课例比较、课程资源、作业和测评。新增知识包只制作独立副本；副本上传前必须通过稳定身份、隐私和清单哈希校验。远端先以两篇并行验证，再以最多三篇并行检查队列与耗时，记录 `DONE`/`FAIL` 终态与 chunk 数，不自动重试失败论文。旧两篇技术失败单列分析，不归入学术质量裁决。

二十篇结束后逐篇审阅专业准入、题名与实际方法一致性、实施/设计/效果边界、候选档位、正文引文、Tree 来源、原生 Graph 重复及缺来源关系、Wiki 页面覆盖、混合检索与图片投影。核验层与 RAGFlow 原生 Artifact 分开报告，不能把本地投影称为已写入 RAGFlow Artifact 页。

图片库回执键同时包含稳定 `paper_id` 与包内相对路径，避免二十篇都含 `ragflow_assets.md` 时互相覆盖。原图须在包中有批准的隐私状态与一致哈希；图片检索投影和图表写作参考材料单独作为辅助角色入图片库，不能充当正文已执行步骤的证据。

身份核对后来发现更严格的一层：旧知识包清单的 `paper_id` 是稳定编号，交接块同名字段却曾是 `AUTO_...`。仅检查交接块的 `stable_paper_id` 会漏掉这个歧义。教育试验副本改为清单和交接块的 `paper_id` 都使用 `paper_...`；原预处理编号单列 `document_id`。教育 Pipeline 按此契约校验，旧线上试验文档需在新副本完成解析与来源核验后逐篇替换。共享财会链路继续保留自身旧交接约定。

正在运行的 `AUTO_20260924_215028_e9790d` 批次由旧 Python 进程生成；只读扫描时已生成的 247 个源知识包均为旧交接块，且缺少 `stable_paper_id`。这些原始输出尚不能直接作为教育库上传输入。当前二十篇使用独立规范副本，源批次在运行期间保持不变；批次结束后须另行重建或修复待上传包并重新校验哈希与审核回执。新进程使用的教育类导出默认写规范身份，完整教育知识包的上传入口会在网络发送前拒绝旧交接块。

已准备 `education_batch_canonicalize.py` 处理这次正在运行的批次：只在批次状态为 `completed` 时将尚未上传的教育类通过包复制为规范身份副本，逐篇核对原审核指纹、知识包清单和新交接块，再原子更新批次清单中的包路径及审核指纹；原包保留。运行中或已有上传回执的条目拒绝自动改写。运行中的批次只读预览查出 241 个待修复包，`--apply` 被状态门禁拒绝；这个数字仅是扫描时点，并非批次最终数量。

## 扩样中发现的边界

- 预处理专业为“体育教育”仍可能出现竞技赛事技战术或商业俱乐部经营论文。专业标签只是第一道粗筛，论文主体必须确实研究教学、学习、课程、教育评价、学校体育训练或相应教育实践。首轮两篇此类文档恰好也在远端技术解析失败；失败原因尚无服务端诊断，不能将技术失败当成学术剔除。保留其失败档案，另选教育对象明确的训练实验与识字课例补足二十篇有效试跑。
- 题名带“设计与实施”不代表作者实际完成了设计部署或效果评估。无纸化测评样本的正文只证实师生问卷、访谈、人数比例统计与策略提出，归入调查诊断。课程资源开发样本完成了文献和已有案例分析及任务群建构，不能写成课堂实施。
- 两篇试验 `ingest.md` 曾把问卷题项识别成章节；预处理标题判断已加入保护，修复副本须重新解析并验证 PageIndex 才能替换。另一篇源文件把摘要与目录放在前置“参考文献”标题下，保留为来源结构待复核，不自动改写原文。
- 核验版 Wiki 只收正文证据、稳定身份和章节来源同时通过的论文。Tree 有疑点时保留诊断记录，暂不进入核验导航。图片库也只索引远端主文档 `DONE`、裁决“入库”且稳定身份一致的辅助材料；失败或仍在解析的论文不进入可检索辅助库。
- 三节识字课例逐篇分析没有形成明确的课例间比较，因此受控 L2 新增“多课例分析”，不塞进“课例比较”。区域活动中幼儿争抢事件的自然观察另用“儿童行为观察研究”，不把幼儿园区域活动称为课堂观察。
- 实验论文的“随机分组”和识字论文的“分环节品评”虽然在正文有证据，模型给研究步骤选的引文没有直接支撑这些措辞。核验层记录人工复核的替代引文，须在同篇可用正文 chunk 中精确定位后，才把对应步骤及材料边加入投影；原生模型输出仍留作诊断。
