# 工作台共用导入队列

## 已接入的入口

| 入口 | 持久化意图 | 解析对象 |
|---|---|---|
| 自动预处理 | 每篇保存后立即入队；批次结束补漏 | 主 `ingest.md` |
| RAGFlow 页“导入选中项” | 使用手选 md / 图片目标 | 主 `ingest.md` |
| 手动上传按钮 | upload_only，手动优先级 | 不新增解析意图 |
| 队列结果“重试选中项” | 核验原文档后登记明确的第二轮复核 | 沿用原主文档 ID |

同一服务、目标库、稳定来源 ID 和角色对应一个队列任务。上传后追加解析请求沿用原远端 ID；不同内容或冲突的 Pipeline 进入版本冲突处理。旧上传/解析回执不确定时只核查远端，不能因 UNSTART 或超时再次 POST。

旧回执接管检查内容哈希、远端 ID 和名称；多个不同远端回执阻止自动选择。旧解析意图不会被后来的 upload_only 请求取消。正常批量交接共用一份 manifest 快照并一次保存投影；无效项单独处理。任务表按索引选择可用通道，不扫描十万条被容量限制挡住的任务。

## 专业与 artifacts

教育默认路由继续使用用户指定的教育 md / 图片库和已验证的教育 Pipeline；明确手选目标优先。教育适配器统一稳定身份、角色与通道，图片和参考投影只上传，不进入论文标注、Tree 或 Graph。

财会沿用其专业映射及 Pipeline；队列的稳定来源 ID 与财会交接中的旧任务 ID 分开保存。财会裁决按已核验交接 ID 识别，未修改财会标注、Profile、四级分类或 Graph DSL。财会真实新增上传样本未执行，以遵守保留现有财会库的约束；入口和分类用离线样本验证。

专业 Pipeline 继续负责学术准入。工作池负责补位，暂缓、剔除、技术待复核、裁决不明均是第一轮终态，不自动再排队，不附加原来的 120 秒等待。入库后的目录和方法 artifacts 收尾失败独立登记，不阻塞其他解析。

## 状态与恢复

界面区分排队待上传、上传中、待核查、已上传、解析排队及终态。没有远端 ID 的任务不会显示已上传。批量读取队列状态，保留原回执视图；明确第二轮复核按钮继续复用原文档。

后台 worker 读取该工作台数据目录的 DPAPI 凭据，队列不存密钥。文件锁阻止重复启动，工作台入队后按需启动 worker。HTTP 429 暂停受影响服务的写入；明确的模型欠费停止该通道的后续解析，其他通道可继续。

## 生效与限制

`work_pool_enabled=true`，自动启动开启，解析上限为 6。教育库在 dataset 元数据未绑定 Pipeline 的情况下，通过本地已核验的 dataset → Pipeline 映射绑定新文档，保持专业 DSL 原样。

已恢复旧批次 worker，原批次当前预处理 interrupted，暂无新论文积压。完整加载新入口需重启工作台；之后新批次和手动任务共用队列。没有创建新的 Codex 自动化。

30 篇远端验证、时间和质量边界见 [工作池实测](2026-09-26-ragflow-work-pool-core-verification.md)。本次试跑是原失败论文的复核，没有新增重复主文档。模型输出契约及失败原因仍须在后续质量复核中解决。
