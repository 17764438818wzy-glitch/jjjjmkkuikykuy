# 论文知识库全自动预处理工作台

新批次：原稿登记 → 程序准备完整正文和图表 → 同一图文模型按现有 MD 完整提取 → 程序校验、基础脱敏、切片和封包 → 成品落盘排队 → RAGFlow 向量化、索引和逐专业读回确认。

现有 MD 的字段、完整学习内容和来源要求继续保留。整篇可容纳时一次请求；容量不足时复用程序自动分段和装配。已有完整回答优先复用，失败或未决请求不会自动重发。非关键格式问题沿用兼容规则，缺少影响实际学习的内容时保留明确缺项。

## 使用

1. 双击桌面“论文知识库预处理”。
2. 在“Agent 模型”的“全文与图像提取模型”中选择支持图像的通道并保存。新提取由同一模型读取全文和实际图像；“旧格式图表通道”保留历史恢复用途。密钥通过 Windows DPAPI 加密保存。
3. 在“RAGFlow 连接”配置服务地址和密钥。新批次使用 MD 最终专业名单及现有目录分别入库，三级专业继续独立；单库选择保留给旧格式。只做本地处理时点击“稍后入库”。
4. 选择源文件夹、扫描、全选/取消全选/反选，然后开始。进度窗口显示每个处理阶段。
5. “选择与处理”记录程序准备和后处理；“AI 处理结果”保留模型回答、提取结论及校验反馈；“RAGFlow处理结果”显示各专业的排队、上传、内容和图片读回及检索确认。只有全部目标确认才算完成。后台交付继续时，停留 RAG 结果页也会自动刷新。
6. 完整模型回答保存后释放名额，按统一启动间隔递补。当前桌面配置为模型 10 路、至少每 16 秒启动一篇、本地后处理 2 路、成品交付 4 路；真实十路验收见原流程说明及本地回执。本地结束不代表全部已入库。停止本地处理会保存进度，已登记的成品继续按原上传队列交付。重开原窗口后继承保存设置。

当前桌面通道已同步为本轮已验证的图文 CLI 通道，输出上限 128000，超时 3600 秒。接口和密钥仍从原设置表单读取，不硬编码到程序。完整接线和恢复边界见 [原流程说明](docs/single-request-preextract.md)。

详细配置、JSON 协议、数据流、失败处理和限制见 [AI接口说明.md](AI接口说明.md)。

## 旧格式的保留功能与历史输出

以下描述旧格式结果及其原恢复、交接方式；新批次采用上面的完整提取与现成切片投递路径。

- 原文件只读，Office 使用现有 LibreOffice 转换，原脱敏规则和中文专业词表继续复用。
- 粗筛仅排除明确非论文和可靠提取后确实不足 3000 有效字符的材料。扫描件、低文字量图片文档和解析异常不能直接按字数筛除。
- 保留标题、正文顺序、表格单元格、财务数值、公式及图片；自动删除致谢。复杂对象交给 AI 根据原文证据补充，不靠重画图片补全。
- 图片分类与真实预览、处理日志、开始停止、全选取消反选、历史记录、导入去重及文件版本校验。
- 预处理结果与 RAGFlow 处理结果分栏显示；RAGFlow 页可刷新远端文档的解析进度，不把“未上传”误报为 Pipeline 不通过。
- 不进行学历适配或学术质量评级；后续专业 Pipeline 由 RAGFlow 承担。

## 输出

“打开批次目录”进入中文结果目录：

```text
通过/
  会计学/
    论文题目.md
不通过/
  会计学/
    论文题目.md
```

尚未识别专业的材料放在“未识别专业”。同名文件追加短编号。专业文件夹直接放文档，没有每篇一层目录；不生成有争议目录。技术失败也生成中文原因说明。历史未完成的结果显示不通过，保留历史记录原意，需要重新处理才能获得新流程通过结论。

程序内部保留每篇的 document.md、ingest.md、assets、metadata.json，支持图片引用与证据追溯。源副本和脱敏前的临时资料只放在内部 private 目录。用户浏览文件依赖程序的图片资源，单独复制 Markdown 不会同时带走图片。

RAGFlow 会接收 `ingest.md` 和同稿的 `ragflow_assets.md`。前者用于正文检索，后者提供图表类型、坐标轴、系列、表格字段和原始数值等机器可读写作配方；知识包中已通过脱敏检查的图片也会作为独立文档上传到同一个专业知识库。上传记录会保存每个辅助文档的远端编号，遇到网络中断时先核对远端状态再重试。

原生表格校验行列结构并保留原值；表头未明确时保留候选说明与原坐标，不把推断标成已核对。目录、已删除封面不触发 AI 全文扫描。PDF 矢量图、扫描页、嵌套表格等只识别相关页；无法可靠定位或恢复则不通过。图片若被后续文本检查发现额外敏感信息，会直接不通过，不只改 OCR 而保留原像素。

`automatic_approval=true` 表示通过本流程检查，`completeness_verified=false` 表示没有额外进行独立的逐页全文比对；两者不等同。学术评级和客户适配仍在后续流程。

### 教育类论文的交接身份

新启动的预处理进程导出教育类知识包时，清单、`ingest.md` 和 `ragflow_assets.md` 的 `paper_id` 都使用稳定 `paper_<24 位哈希>`；预处理任务编号另放在 `document_id`。上传完整教育类知识包前会核验这三个文件的交接身份与内容哈希，不一致即停止发送。财会类旧交接约定保持原样。

如果教育批次在本次代码更新前已经启动，其进程仍可能生成旧交接块。等该批次状态成为 `completed`，先只读预览，再为尚未上传的通过包生成规范副本：

```text
python -X utf8 education_batch_canonicalize.py <批次编号>
python -X utf8 education_batch_canonicalize.py <批次编号> --apply
```

修复工具保留原包，逐篇更新批次记录里的包路径与审核指纹；运行中批次和已有上传回执的旧包不会自动改写。二十篇教育试跑的核验结果见 [扩样报告](docs/superpowers/specs/2026-09-25-education-20-pilot-audit.md)。

历史批次保留原格式和记录；新流程不沿用旧版人工确认，需从源文件重新处理。
